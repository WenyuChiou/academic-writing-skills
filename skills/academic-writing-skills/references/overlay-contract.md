# Overlay Contract

## Purpose

Use an overlay to add context without changing the universal integrity core. An overlay may come from a domain skill, professor or reviewer rubric, journal guide, reporting standard, or project record.

## Required Classification

Classify every overlay rule as one of:

1. **design requirement:** follows from the declared study design
2. **domain check:** tests terminology, mechanisms, customary evidence, or field practice
3. **reviewer preference:** controls tone, structure, emphasis, or revision-round behavior
4. **venue requirement:** follows from an identified journal, conference, institution, or reporting standard
5. **project state:** supplies facts, locked wording, decisions, files, or prior-review status

Do not present categories 2–5 as universal scientific requirements.

## Precedence and Conflict Handling

Apply this precedence:

1. safety, ethics, and research-integrity constraints
2. verified evidence and authoritative project facts
3. explicit current user instructions
4. applicable venue or reporting requirements
5. study-design checks
6. domain conventions
7. reviewer preferences

When two sources at the same level conflict, report the conflict and identify what authority is needed. Do not silently choose the wording that sounds more polished.

## Safe Composition

Before applying an overlay:

- confirm the manuscript is within its scope
- load only relevant reference files
- state which rules are requirements and which are preferences
- identify any rule that would change locked meaning, add unsupported mechanism, or force an unsuitable article structure
- retain project-specific content outside the reusable skill

During review:

- use the universal issue severity and evidence-status model
- let the overlay calibrate attention, tone, and specialized checks
- preserve the manuscript archetype and study-design adapter
- require evidence for “why,” causal, validation, novelty, and feasibility claims

After review:

- report which overlay was applied
- identify conflicts, exceptions, and waivers
- include the functional-completeness retrospective

## Reviewer-Round Overlays

Treat review round as maturity, not as a guarantee that earlier issues are resolved. Compare current files with prior comments when available. Do not infer progress from comment count alone.

In later rounds, prioritize unresolved blockers and regression from new edits. Avoid inventing new discretionary concerns when the manuscript is stable, but never ignore a newly discovered validity or ethics issue merely because the round is late.

## Prohibited Overlay Behavior

Do not let an overlay:

- require numbered questions, an IMRAD sequence, or a public repository for every paper
- force a mechanism into Results without evidence
- treat one professor's wording preference as universal English
- infer facts or authorship roles from formatting
- conceal a method limitation to match a preferred narrative
- replace a formal statistical comparison with visual similarity
- carry project facts into another manuscript
