## Modes and Lifecycle Stages

Use lightweight mode for bounded text work. Use managed-project mode when the task spans a full manuscript, multiple revisions, material scientific changes, companion artifacts, or release certification.

Recognize these publication states in addition to section development: exploratory draft, complete internal draft, initial submission, revise-and-resubmit, accepted manuscript, and proofs. Narrow the intervention as the state advances. At proofs, make only authorized corrections needed for accuracy, production, or venue compliance; do not reopen settled structure or style without explicit permission.

Distinguish three timelines:

- **writing sequence:** the order in which authors develop sections
- **evidence dependency:** later analyses constrain earlier framing and later summaries
- **review maturity:** developmental, substantive, integration, and submission stages

Do not mark a section permanently complete. Mark it current relative to a named evidence state or release candidate.

## Reader-Function Mapping

Map actual sections to reader functions before applying structural rules.

| Reader function | Empirical article | Review or synthesis | Framework or methods | Theoretical or conceptual |
|---|---|---|---|---|
| Problem and gap | Introduction | Introduction | Need and limitations | Problem and conceptual gap |
| Evidence source | Study context and data | Search and screening | Requirements and inputs | Prior theory or premises |
| Analytical process | Methods | Synthesis method | Framework or algorithm | Argument or derivation |
| Main contribution | Results | Evidence synthesis | Verification or application | Propositions or implications |
| Interpretation | Discussion | Discussion | Evaluation and implications | Boundary conditions |
| Final synthesis | Conclusion | Conclusion | Conclusion | Conclusion |

Do not require headings such as `Study Area`, `Methods`, or `Results` when the genre supplies the same functions differently.

## Review Maturity

- **Developmental:** test gap, purpose, architecture, missing functions, and method feasibility.
- **Substantive:** test evidence alignment, method completeness, technical precision, terminology, and figures.
- **Integration:** test cross-section propagation, interpretation, limitations, summaries, and remaining blockers.
- **Submission:** test exact files, metadata, references, formatting, rendering, and venue requirements.

For revise-and-resubmit, map every reviewer request to the changed evidence and response artifact. For accepted manuscripts and proofs, treat authorship, results, equations, citations, and production metadata as protected high-risk fields.

Review maturity does not equal section order. Re-open the Introduction at integration stage if Results changed the supported claim.

## Stage Gates

### Project and outline gate

Identify the active project, sources, archetype, intended audience, gap, objective or questions, outcome, contribution, and nonclaims. Ensure every planned question has a plausible evidence route.

### Context and Methods gate

Trace data or premises from source through preparation, measurement, model or analysis, diagnostics, and output. Separate reproducible procedures from contextual description and later interpretation.

### Results gate

Build findings from verified outputs. Give each objective or question a substantive answer. Identify orphan methods that produce no reported result and orphan results with no described method.

### Discussion gate

Separate direct findings, supported mechanisms, interpretations, alternative explanations, implications, and speculation. State how each limitation changes inference or generalizability.

### Conclusion and summary gate

Synthesize current evidence; do not copy an earlier abstract. Preserve the study task and scope. Do not introduce new evidence or silently promote comparison to validation.

### Companion and release gate

Synchronize supplements, figures, tables, metadata, cover materials, and repository statements. Inspect the exact active files and block release when required evidence or high-severity issues remain.

## Change-Impact Classes

| Class | Examples | Minimum recheck |
|---|---|---|
| A: semantic contract | gap, SQ, outcome, task verb, contribution | whole evidence chain; title, abstract, highlights, conclusion, submission summaries |
| B: evidence or method | sample, model, analysis, number, figure, limitation | source, Methods, Results, interpretation, visuals, supplement, summaries |
| C: metadata | authors, roles, funding, affiliation, declarations | all submission files and metadata forms |
| D: surface | grammar, punctuation, formatting | local semantic diff, protected contexts, render |

When one edit contains multiple classes, apply the highest-impact recheck plus every artifact-specific check.
