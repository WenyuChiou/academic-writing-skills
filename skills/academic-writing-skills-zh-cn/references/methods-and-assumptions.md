<a id="scope-and-reader-functions"></a>
## 处理范围与读者功能

Methods 说明本研究如何产生回答问题所需的证据，并提供足够的细节以理解并重现重大的程序。请使用下列功能规划所要求的单元，而非将其视为五个强制的子章节。应使用 [study-design-adapters.md](study-design-adapters.md) 将其调整适配至实际的研究设计。

| 读者功能 | 相关时应提供的信息 |
|---|---|
| 理解整体研究取径 | 研究的单元、拟进行的比较，以及主要步骤如何与研究目的连结。 |
| 理解输入资料 | 资料来源、选取、测量，以及实质转换或指派。 |
| 跟循程序步骤 | 输入、操作、产出以及相关的先后顺序或相依性；符号使用前应先定义。 |
| 理解重大选择 | 何者来自证据、研究者做了何种选择、为何该选择是合适的，以及何者仍属假设。 |
| 理解评估与设计 | 与研究设计及主张相关的实际比较基准线、诊断、校正、验证、不确定性或敏感度分析程序。 |

撰写程序性段落时，开头应先明确说明其角色，接着解释其如何运作以及任何重大的基本原理。应在相依操作之前先引入前置条件，而非让读者从后续文本中拼凑其先后顺序。切勿对每个例行步骤都加入冗长的辩护。正文必须保留核心逻辑；补充材料可收纳详细设定或推导，但不能取代理解该方法所需的必要说明。

<a id="separate-origin-application-and-evaluation"></a>
## 区分来源、应用与评估

有来源出处的参数并不等于毫无假设的参数。应检核三个独立的问题：

1. **来源：** 该数值、分布、关联或规则源自何处？
2. **应用：** 它在此处如何被使用，以及有哪些额外选择使该使用成为可能？
3. **评估：** 有何证据评估了该使用，且该项评估实际上确立了什么？

这些类别可共存于单一设定中。例如，某个数值可以是在资料上配适拟合、在某个假设下转移套用至另一个母体，并在敏感度实验中进行检验，但未经外部验证。

| 来源 | 准确回报 | 切勿暗示 |
|---|---|---|
| 观察或测量所得 | 资料来源、相关单位，以及其使用所需的任何测量或前处理。 | 合成指派是观察到的住户或现地记录。 |
| 实证估计或配适所得 | 提供该数值或关联的资料与估计程序。 | 横断面配适可识别时间动态或因果机制。 |
| 校正所得 | 所调整的参数、校正目标或标的、资料与程序。 | 配适某一目标即可验证每个模型组件或独立预测。 |
| 采纳自既有研究、手册或默认值 | 该来源提供的确切设定及其与当前使用的相关性。 | 定性论理可提供具体数值，或默认值是在现地估计所得。 |
| 作者假设或简化 | 所选规则或数值，以及简要且针对本研究的论理依据。 | 仅因相关概念有文献引用即代表其已获实证识别。 |
| 情境或敏感度设定 | 实验变更、比较基准线与目的。 | 测试的范围是估计的信赖区间，或稳健性可证明规则正确。 |

应用假设可能涉及尺度、母体或时间的移转套用、指派通用数值、将变数固定、独立性、操作门槛或更新规则的形式。应指明实际的假设，而非将每项设定都称为 “data-based” 或 “assumed.”。未知的来源在经过检核前仍属于未核实；切勿擅自将其归类为作者假设。

验证各文献引用所支持的项目：数据、方程式、定性论理、制度背景或评估主张。支持某单一角色的文献引用并不会自动支持其他角色。应明确区分程式码验证、校正、实证验证与敏感度分析。模型中所呈现的机制，并不能作为该机制导致了所观察到真实世界结果的证据。

<a id="explain-consequential-choices"></a>
## 说明重大选择

对于攸关诠释的重要设定，应保留这份精简纪录的相关部分：**所规定的项目**（在适用处包含数值与单位）、**其来源**、**其如何被应用**、**其余的假设与论理依据**，以及**有何评估予以支持**。当有多个设定需要比较时，请使用简明散文或表格；无须为每个例行参数都建立流水帐。

在首次相关操作使用处，即应说明重大假设。陈述促成该假设的实际研究目的、证据限制或模型简化。“This is an assumption” 能标明状态，但并未回答为何做出该选择。除非已有确切根据，否则切勿捏造论理依据或将缺乏资料说成是原因。相关的研究限制界定了诠释范围；但这不能成为在 Methods 中将操作规则交代不清的借口。

在稽核既有文本时，首先应比对其主张与现有来源及实作。修复夸大陈述或缺失的区分，但切勿暗中更改设定。若无法取得必要证据，应标记确切的未知事项并限制该主张。编辑请求并未授权进行新的校正、敏感度执行或替换参数数值。

<a id="hypothetical-examples"></a>
## 假设性范例

以下为教学用的假设性范例，并非对任何稿件的已验证描述。其中不含可重复使用的数值设定或文献引用。应借鉴其区分方式，而非其科学主张；仅在相应程序已确认时，方可使用范例措辞。

<a id="a-a-fitted-starting-distribution-and-an-assumed-time-rule"></a>
### A. 配适所得的初始分布与假设的时间规则

假设调查资料提供了某项行为特征的初始分布，但模型在时间推移过程中将该特征固定不变。

- **源自证据的部分：** 配适拟合的初始分布及其参数。
- **假设的部分：** 时间上的恒常性。若将其独立指派给各代理人，这是一项单独的选择，而非配适分布所得的必然结果。
- **可能的措辞：** “The initial trait distribution is fitted to survey responses. We hold the trait fixed during the simulation because the survey does not observe within-person changes over time.” 仅在调查与建模论理确实予以支持时，该原因方可使用。

切勿将其压缩为 “the behavioral dynamics are calibrated using survey data.”。该项调查可能支持初始化，但并未识别时间动态。同样地，手册可提供初始数值，但将该数值套用于模型中的每个住户依然属于简化处理。

<a id="b-institutional-background-does-not-estimate-an-adoption-threshold"></a>
### B. 制度背景并非估计采纳门槛的根据

假设现实世界的保险规则为两个群组提供了采用不同采纳门槛的动机，但具体的数值区间是由研究者所选定。

- **有来源支持的部分：** 相关的制度区分，包括该规则适用的条件。
- **假设的部分：** 所选定的数值区间及其作为代理变数的使用，而非明确执行该机构的制度规则。
- **可能的措辞：** “The institutional distinction motivates separate adoption thresholds for the two groups. The intervals are model assumptions; the cited policy does not estimate their values.” 若已知选定该区间的实际原因，应予说明。

单纯引用该项政策并无法支持 “thresholds estimated from the policy.”。任何敏感度评估皆应另行回报；在测试区间内产出未变更，并不能验证原本的区间。

<a id="c-a-published-community-level-formulation-applied-to-individuals"></a>
### C. 将已发表的社区层级公式套用于个人

假设模型改编了已发表的社区层级记忆公式，利用当地总体损失来更新个人认知。

- **有来源支持的部分：** 其所陈述分析层级上的原始公式。
- **假设的部分：** 个人层级的套用，以及将总体损失作为讯号（反映出除了个人损害之外，亦可能受到社区洪灾经验的影响）。
- **可能的措辞：** “We adapt the community-level formulation to individual perception and use local aggregate losses as the update signal. This assumes that perception can respond to community flood experiences, not only personal damage.” 若有佐证，应将该论理依据的支持文献与公式来源分开引用。

除非有证据确立该主张，否则切勿将此移转套用描述为经实证验证的个人更新。共享总体讯号亦不代表已对住户互动、信息传播或社群网络学习进行了明确建模。

<a id="d-qualitative-sampling-and-an-unsupported-coverage-claim"></a>
### D. 质性抽样与缺乏佐证的涵盖范围主张

假设访谈采用立意抽样与反身性主题分析。招募程序与编码方法皆可详实记录，但这并未确立母体盛行率或饱和度。应说明实际的选样论理与分析流程；切勿仅因 “representative” 或 “saturation achieved” 这些词汇常出现在 Methods 中就迳行添加。若经确认且相关，应指出研究者立场与反例处理方式。

<a id="e-a-theoretical-premise-and-a-proved-conclusion"></a>
### E. 理论前提与经证明的结论

假设针对具有非负容量的图推导出一个定理。应将陈述的前提与透过证明所确立的结论明确区分开来。切勿将该前提描述为经实证校正、切勿强求实验资料集，亦切勿在缺乏支撑论证的情况下将结论延伸至负容量。此处的可重现性是指具备可供检视的推导过程与定义，并不一定代表需要随机执行。

<a id="design-dependent-hidden-failure-checks"></a>
## 视研究设计而定的潜在失效检核

在程序与来源出处皆清楚易懂后，请检查下列相关的比较与相依关系。这些是诊断性问题，并非要求在每种研究设计中都加入所有分析、假设表格或研究限制。

| 潜在的隐含问题 | 在接受该诠释前应先确立的事项 |
|---|---|
| 群组比较同时改变了数项初始条件 | 哪些属性或条件存在差异，以及该设计实际隔离了何者？描述性的群组比较不必然要隔离特定路径，但切勿将其呈现为因果效应。 |
| 摘要统计掩盖了运算顺序 | 比率是在聚合之前还是之后计算？使用了哪些权重？分母是初始值还是当前值？单元比率的平均值与总数的比率，未必回答同一个问题。 |
| 变动的群组平均数看似个体的变动 | 观察对象是否追踪相同的单元，抑或搬迁、退出或重新分类会改变成员组成？在现有证据允许的范围内，应区分单元内部的变动与组成的变动。 |
| 重复执行看似额外的实证观察 | 重复执行是相同输入的随机实现、新的观察值，还是独立的实验单元？说明所回报的变异性代表何者，以及其未涵盖哪些不确定性。 |
| 评估与输入资料或配适目标重叠 | 哪些资料与转换在校正与评估中被重复使用？揭露该项相依性，并使评估主张与实际证据相符；独立的外部验证并非每项研究的强制要求。 |
| 某项解释仅仅是重复了程式设定的规则 | 除了规则本身之外，有何产出或诊断可支持该项解释？如 [universal-integrity.md](universal-integrity.md) 所述，应将所呈现的机制、观察到的模式、经检验的解释与未经检验的诠释明确分开。 |

缺乏支持更强烈诠释的证据，并不必然代表该方法有误。应适时限缩主张、指明未解决的区分，或在适当情况下提出具针对性的诊断方案。切勿仅为了完成写作检核，就声称已执行该项诊断，或在未获必要授权的情况下迳行执行。

<a id="scope-aware-revision-checks"></a>
## 具备处理范围意识的修订检核

对于单一句子或段落，检核其切实提及的重大设定以及相邻文本中可用的前置条件。对于 Methods 的小节，追溯其输入、程序、产出与来源出处。对于章节或稿件审查，额外比对相关的参数表、方程式、实作证据、补充材料，以及校正或验证的主张。切勿将所有可能的检核套用于每次局部编辑。

当已获接受或经指导教授编修的基准版本已具备这些功能时，应予保留。仅更正缺失的区分、缺乏佐证的归因、重大的疏漏或受影响的衔接转折。使用 [lifecycle-and-routing.md](lifecycle-and-routing.md) 进行影响扫描；检核某项相依关系并不会扩大写入授权。若无设定变更，切勿暗示模型已重新执行或重新完成验证。

对于跨章节的规划或审查，请使用 [introduction-and-study-context.md](introduction-and-study-context.md) 中的交接检核。局部的程序或文法编辑不需要进行该项完整的跨章节审查。
