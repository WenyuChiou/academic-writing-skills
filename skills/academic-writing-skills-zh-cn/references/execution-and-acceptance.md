# 初稿执行与交付验收

在**首次**交付实质段落或格式化产物之前，即应使用此程序，而非仅在作者发现问题后才执行。它旨在将现有的完整性检核关卡具体化，并未增加固定的文章架构或新的科学标准。单凭语言扫描绝不代表章节验收合格。

<a id="select-the-stage-checklist"></a>
## 选择阶段检核清单

请综合考量行动、要求的单元、变更影响与可用来源。同一共享的项目状态提供了术语、事实、决定与未决问题；以下是该项工作的不同检视面向，而非五本新的纪录册。现有的大纲或写作约定若仍与当前的证据相符，即可作为计划依据。

| 检核点 | 执行项目 | 保留或参照内容 |
| --- | --- | --- |
| 大纲／章节规划 | 指出读者必备先备知识、段落功能、证据位置、推论界线与桥接句。将各段主题句通读为一条连贯论点。对于现有大纲，请检查其实际功能，切勿虚构更理想的过程。 | 功能顺序与证据需求；缺乏支持的结果仍列为需求。适配于概念性、质性与其他研究设计，不强加 IMRAD 架构。 |
| 段落起草／实质重写前 | 确立功能、主张、证据、推展与桥接句；在着手措辞前先排列句子顺序并检查可用的相邻文字。 | 精简的写作计划或相关现有大纲／约定的定位标记。纯文法修复需保留原意，无须拟定新计划。 |
| 编辑后交付 | 使用以下适用的检核项目检查确切的候选文本；将其与计划、原意、来源及相邻行文进行比对。 | 候选对象／版本、具体定位的发现、解决方案与剩余限制。一次性的对话编辑可直接内嵌记录。 |
| 章节结尾 | 通读全章的各段开头与结尾；检查其解答以及生命周期指南中与研究设计相关的盲点。核对已确认术语、提议、决定与未决问题。 | 实际发现的章节摘要、选定诊断检验及其证据界线，以及对共享词汇的变更或确认维持原状。 |
| 全文审查 | 完成四轮检验：论点／结构、证据／处理范围、学术写作、交付完整性。仅在属于处理范围内或被触发时，才检查受影响的附属产物。 | 各轮检验分别定位的结果与功能完整性回顾。切勿以一次无问题的语言扫描取代全部四轮检验。 |

在撰写新行文之前，请先记录起草前计划；切勿事后补记笔记并宣称这确立了该顺序。纯审查任务仅评估现有文字，不需要假装执行了起草前计划。对于小节／章节的实质工作，请在该单元内执行四轮检验，而非无关的章节。全文件的标点符号检核依然不能等同于科学性的全面审查。

日常的交付请保持简短：通常只需说明检查／变更了什么以及具体的剩余限制即可。在章节／全面审查的交界处，请扩充记录，让下一轮可以重复使用既有决定并找出未解决的项目。切勿详述每一对句子的检查过程，亦勿为每个段落单独建立文件。「无问题」的结果仍应指出具体段落与实际检查的内容；千篇一律的保证并不是证据。无法取得的来源仍应标记为无法取得，而非合格。

<a id="before-writing-agree-on-the-readers-route"></a>
## 着手写作前：就读者的阅读路径达成共识

重复利用现行的约定与来源。指出读者可能具备的知识、所比较的单元、段落功能以及最低限度的先备条件。针对章节工作，请在起草前写下简短的功能顺序：确立了什么、接下来增加了什么，以及该顺序回答了什么问题。针对有界限的个别段落，仅需检查现有的相邻文字。切勿默默捏造缺漏的背景脉络，亦勿因局部修改而强行全面重写整篇论文。

对于研究摘要的实质修订，在动笔措辞之前，请先使用 [conclusion-and-abstract.md](conclusion-and-abstract.md) 中的研究定位准备。找回当前的研究目的与各个研究组件的角色，包含比较单元／维度／层级与相关的处理范围；重新利用现有的段落计划。研究目的与用以达成该目的的方法或资料集不可相互混淆。作者已锁定的段落顺序决定了研究定位、研究发现与延伸检验各自的归属。这不会被纯表面修改中的章节关键字所触发，也不需要作者重复目前「引言」（Introduction）中已有的背景脉络。

在展开从属细节之前，请先确保主要比较清晰可见。若作者要求进行人类与大型语言模型的比较，请在介绍个别大型语言模型之间的差异之前先引出该项比较。在其他研究中，主要对照可能是处置、区域、理论或时期。**「人类优先」是个别项目的选择，并非普遍通用的规则。** 定义与专门术语必须在读者需要之前呈现；解释它们的作用，而不仅是展开缩写。

对于图表展示，在撰写图说明之前请先分配好信息：

- 图说明：展示了什么，以及独立解读该图所需的关键要素。
- 正文：有证据支持的发现、比较、诠释与下一步。
- Methods／补充材料（SM）：延伸程序、挑选规则、设定或诊断检验。

从图说明中移除重复的程序，但若省略会误导读者，则请保留关键的样本／运行惯例、不确定性定义、分母或排除条件。切勿强制实施通用的图说明字数限制。

对于流程描述，请对整个要求的单元及其受影响的相邻文字套用 [workflow handoff test](prose-and-citation-editing.md#workflow-handoff-test)，而非仅针对加上注解的片语。请保留清晰且已被接受的文句与科学意涵；这不会触发无关的全篇论文审查或额外代理人。

对于锚定修订，在起草之前请使用 [comment-scoped-revision.md](comment-scoped-revision.md)。绑定目前的来源杂凑值、生效的选定措辞、完整讨论串与要求的行动；阅读周围行文但切勿解除其锁定。事后比对来源与候选文本，指出实际变更与未变更的句子，并为任何最小限度的扩充找出证据。文件编辑、回复与结案处置应分别取得授权。不确定或过时的锚点不能视为通过处理范围检核；选取范围外的零差异不能作为破坏依赖关系或缺乏答案的借口。

<a id="before-handoff-perform-then-record"></a>
## 交付前：先执行，后记录

对于意见导向的工作，请使用现有的 [comment-scope procedure](comment-scoped-revision.md#test-concern-closure-separately-from-edit-completion) 分别记录编辑完成与疑虑结案状态。在目前的阅读单元中定位原始问题的答案，或指出仍未回答／未核实的部分。无问题的措辞扫描、选取范围的变更或精确的差异对照皆不代表该项判定。请重复利用现有的发现或纪录册；不需要新的结构描述、固定的句型或全篇论文稽核。

在完成最后一次编辑后，请检查**确切**的候选文本及其受影响的依赖项。针对每项适用的检核记录一笔已定位的发现；勾选标记或千篇一律的保证并非检核已执行的证据。现有的项目笔记即可容纳这些记录。对于局部的对话编辑，简洁的内嵌记录已足够；切勿仅为了修改一个句子就建立项目状态或 JSON 文件。

| 检核项目 | 必要行动与验收证据 |
| --- | --- |
| 意涵与证据 | 将候选文本与已确认且不可擅改的决定之原意及来源证据进行比对；定位任何变更的主张或引文。对于纯文法工作，请保留未变更的已核实支持内容，切勿宣称进行了全新的文献稽核。 |
| 语言扫描 | 对这些位元组执行适用的术语／套话检核，并解决或明确保留每一项脉络发现。扫描的 `PASS` 仅涵盖该次扫描。 |
| 读者通读 | 在首次交付之前，以及后续任何实质行文编辑之后，请由了解广泛领域但不熟悉本研究内部速记的跨领域知情读者进行通读（或模拟冷读）。对于实质的段落或章节工作，请检查**每一对相邻句子**：说明下一句增添了什么以及为何承接前一句，接着指出文本中能让读者建立该连结的证据、比较、指涉对象或先备条件。检查不明确的主体、专业术语、比较与指涉对象。若无法在不依赖隐藏项目历史的情况下从段落转述其关系，请修复顺序、内容、指涉或限定条件；删除多余的句子可能是最小修复方式。单纯添加转折词并非修复。切勿强求每句之间都必须有明确的连接词，亦勿纯粹为了句型变化而重写必要的专业术语重复。接着转述该段落能让读者得出什么结论。在可行时，真实的独立冷读者对复杂章节或重复出现的理解失败很有帮助；切勿凭空捏造。 |
| 推进与铺陈 | 对于实质工作或章节／投稿文件，请依序通读各段开头与结尾。记录每个段落增添了什么以及每个边界处的实际关系。修复重复的功能、跳跃以及偏离作者锁定之比较的情况；单纯添加连接词无法修复逻辑。 |
| 研究限制定位 | 当研究限制属于处理范围时，请将资料、指标、测量、模型或研究处理范围中的选择、不确定性或设计边界，与可修正的错误或遗漏的必要工作区分开来。对于真正的研究边界，请指出有据可查的来源或条件、其所导致的不确定性，以及所限制的具体结果或推论。在描述不确定性之前请先加以查证；切勿推断偏误方向或宣称论文有缺陷。请修正可修正的错误，或准确回报未解决的必要工作，切勿将其重新标记为研究限制。 |
| 图说明分配 | 当图表展示／图说明受到影响时，请将每则图说明与其对应图形、正文以及 Methods／SM 进行比对。定位保留的关键要素与移除的冗余内容；重新检查分图对应、统计数据与引用标记。 |
| 最终排版 | 编辑格式化文件时，请依预期尺寸检查储存后的渲染效果：图说明位置、间距、分页符号、图形位置、易读性与重叠情况。验证直接格式化与继承的样式；除非有经查证的规则或作者要求做出变更，否则请保留正常运作的基准。XML、DPI 与来源影像检查并不能保证嵌入后的排版无误。 |
| 编辑者身分 | 对于格式化编辑或元数据变更，请根据**新**修订／意见／回复作者与适用的文件属性，查证明确预期的身分。保留历史作者与意见；切勿将所有人重写为目前作者，亦勿从助理／模型名称推断身分。 |
| 发表场域依据 | 当套用发表场域指定的格式时，请指出载明日期之官方要求、作者／项目偏好或观察到的范例。切勿将局部的间距或图说明选择冒充为期刊的强制要求。无法取得的官方指南仍维持未核实状态；暂行格式可在无合规认证的情况下进行。 |

对于明确的独立易读性审查、依赖概念的实质章节，或重复出现的理解失败，请使用 [independent-reader-review.md](independent-reader-review.md) 中限定处理范围的协定。独立读者应在没有作者解释的情况下检查相同的完整单元；当无法取得个别读者时，自我检核仍应如实标注为自我检核。纯文法编辑仍应使用上述的局部通读，而非自动进行多代理人稽核。

当「结果」（Results）行文读起来像零散的笔记时，请在该通读中使用 [result–explanation continuity check](results-and-explanation.md#resultexplanation-continuity)。定位已修复的关系或有正当理由维持原状的发现；句子长度与添加的连接词并非验收标准。

请分开不同的报告基础：扫描报告的是已设定的模式匹配；父层通读报告的是已定位的读者理解阻碍或有正当理由维持原状的发现；独立读者报告则指出该读者的实际处理范围与限制。例如，工作流程发现可以指出某个段落现在提供了下一段所需的更新输入。组件清单或笼统的 "flow checked" 并非那种证据。请将局部发现保留在行内，切勿印出每一对句子的观察或建立另一本纪录册。即使扫描合格，尚未解决的理解问题发现仍应维持未结案状态。

仅在具备具体的定位标记、发现内容以及已解决／未结案结果时，方可使用 `checked`。即使检核已执行，未结案的发现仍属未完成。请明确区分 `not_run`、`unavailable`（附注理由）以及 `not_applicable`（因该检核超出已宣告的处理范围／影响之外）。绝不可将无法取得的来源、作者豁免或无违规的禁用词扫描结果转化为合格通过。缺乏相邻文字会限制连贯性验证，但并不妨碍撰写清楚标注的暂行局部草稿。

对于取决于前后脉络的争议或回归测试练习，请使用相符的 [evidence-context cases](evidence-context-cases.md)。它们能将规则缺失与执行或验收落差区分开来。在测试修复方案时，请保留原始主张与来源事实；若句子改得较流畅却遗漏了比较、改变了测量的构念或强化了推论，则该修复不可接受。

对于多层次的发现，通读时还需定位各个连贯的证据单元在哪里获得其意义，以及下一个单元增添了什么。请检查量值或分析层级的改变，而非仅检查段落边界。最终的综整无法弥补先前缺乏支持的排序或遗漏的比较。请记录实际的阻碍或有正当理由维持原状的发现；连接词、SQ 标签、定义或较短句子的存在，皆不能作为验收证据。在此狭窄的练习中，请使用证据与脉络案例 10 中的实际对照组；切勿因局部编辑而建立第二套检核清单或稽核无关的章节。

对于多层次的比较，请在同一次通读中增添一笔实质的转述：此层次回答了问题的哪一部分、证据在该层次确立了什么，以及下一项比较增添了什么或必须交代什么。定位能让读者在不具备项目历史或 SQ／"first level" 标签的情况下重构这些关系的措辞。若缺乏这种实质贡献，流畅的句对与正确的数字依然不足。当没有后续比较在处理范围内时，切勿捏造桥接句，亦勿将诊断检验视为未说明的许可关卡。失败与维持原状对照组请参见证据与脉络案例 11。自我检核不等同于独立读者结果；交付时请保留此项区隔。

对于摘要性质的行文，同一次通读也需检验读者是否能重构出研究目标与对应的工作，而非仅看到方法或比较的清单。将转述与编辑后确切的候选文本及当前来源绑定；检查文字删减或处理范围修正是否挤压了目标，或是将整体分析与次群体分析混为一谈。定位保留的清晰措辞与修复的逻辑关系，或记录有正当理由维持原状的结果。请参见证据与脉络案例 12。扫描结果、归档计划或 SQ 标签皆不能证明完成的段落已传达了那些关系。

<a id="optional-deterministic-coverage-checker"></a>
## 选择性确定性涵盖检核器

对于重复或多文件的交付，请使用 `scripts/audit_handoff.py RECORD --json` 来验证**涵盖记录**，而非验证其发现的品质或真实性。它不需要受管的稿件状态。若等效请重复使用现有记录；切勿为了符合此格式而捏造第二套记帐系统。

此 JSON 约定支援旧版版本 `1` 与感知阶段的版本 `2`：

- `schema_version`：整数 `1` 或 `2`；`scope`：`sentence`、`paragraph`、`section` 或 `package`；`change`：`surface` 或 `substantive`。
- 版本 `2` 亦需要 `action`：`plan`、`draft`、`revise`、`proofread` 或 `review`；以及 `checkpoint`：`outline`、`handoff`、`chapter_closure` 或 `full_review`。请依据实际的请求／工作来选择，而非选择检核项目较少的设定档。`proofread` 仅限表面。`chapter_closure` 使用实质的 `section` 处理范围；`full_review` 使用 `package` 处理范围。这两个检核点使用 `draft`、`revise` 或 `review`，而非规划或校对。`outline` 检核点用于规划／推展／审查大纲，而非规避行文审查的手段；纯文法的大纲修改使用 `handoff`。
- `features`：四个明确的布林值：`displays`、`formatted_file`、`venue_formatting`、`metadata_changes`。请诚实宣告影响；检核器无法从文件内容推断影响。即使未刻意变更元数据，格式化编辑仍需验证身分。
- `artifacts`：非空的 `{id, path, role, sha256}` 记录清单。路径为绝对路径或相对于涵盖文件的路径；杂凑值涵盖精确的文件位元组。至少有一个角色为 `candidate`；其他角色为 `context`、`evidence` 或 `render`。请纳入检核中使用的目前相邻文字／约定以及受影响的来源或渲染证据，以便在依赖项变更时使涵盖度失效。
- `checks`：来自表格与下方版本 2 阶段检核的适用名称，以蛇形命名法（snake case）表示。每个 `checked` 项目皆具备 `outcome`（`resolved` 或 `open`）、非空的 `artifact_ids`、`locator` 与 `finding`。待处理项目具备状态与 `reason`。
- 已检核的 `final_layout` 参照角色为 `render` 的产物，并在审查发现中与已储存的精确候选对象及渲染程序绑定。已检核的 `editor_identity` 亦记录 `expected_author` 与 `new_edit_authors`；这些涉及本次编辑，而非所有历史作者。清单若为空，则需要 `absence_reason` 记录经检查后确实无新增修订／意见／回复作者以及适用的身分文件属性；切勿纯粹为了通过关卡而填入虚构作者。
- 已检核的 `venue_basis` 亦记录 `basis`（`verified_requirement`、`project_preference` 或 `example`）与 `source`（载明日期之官方来源或明确指示／范例定位标记）。来源字串不由本工具独立查证。

对于无文件／图表展示／发表场域影响且保留原意的句子修改，仅需要 `meaning_and_evidence`、`language_scan` 与 `reader_walkthrough`。对于实质工作，亦需要 `progression_and_framing`。额外适用的检核依据上述影响而定；必要的检核不得标记为不适用。

版本 `2` 新增了以下涵盖要求：

- 针对每项任务执行 `functional_completeness`，其处理范围限于所要求的内容。
- 针对 `plan`、`draft` 或实质 `revise` 执行 `writing_plan`；参照目前大纲／约定，或记录其功能、主张、证据、推展与桥接句。纯审查工作不需要新的起草前主张。
- 针对 `full_review`、全套 `review`，或实质章节／投稿文件的起草、修订或审查，执行 `argument_structure`、`evidence_scope`、`scholarly_writing` 与 `delivery_integrity`。大纲检核点与纯规划工作不会触发这些针对完成行文的检验轮次。
- 在章节结尾时执行 `chapter_closure` 与 `terminology_reconciliation`；全文审查亦需要 `terminology_reconciliation`。未解决的意涵请分开回报。经查证认定术语或决定均未变更的发现是可接受的；切勿为了迎合检核清单而虚构词汇表更新。

对这些检核请使用相同的定位标记／发现／结果约定。若无法取得来源，请将受影响的必要检核记录为无法取得或未结案；切勿以记录的存在将未解决的科学主张冒充为已解决。计划项目可指向先前的大纲；不必将其全文复制。

当检查依赖实际的共享状态、相邻文本、来源与相关规则文件时，请将它们作为杂凑化的情境／证据产物一并纳入。产物一旦变更，该纪录即告失效。检查结果会针对明确宣告的相依项目列出 `stale_artifact_ids` 与 `invalidated_checks`，因此在重新整理杂凑值之前，应保留未受影响的证据，并重新检查受影响的项目。此清单并非语意影响侦测器：若有遗漏或新发现的相依项目，仍需进行判断并扩大影响范围检查。

旧版纪录会保留其原本的处理范围／效果行为并回报 `coverage_basis: legacy_v1`，且不具备工作流程覆盖率。若未明确升级至版本 `2`，便无法宣告新的工作流程栏位或阶段检查。版本 2 的结果会回报 `coverage_basis: workflow_v2`；这代表已宣告的阶段覆盖范围，而非执行证明。切勿重写旧凭证，假装新检查已经执行过。对于局部编辑，行内发现事项仍属可接受；JSON 检查器为选用性质，不会强制要求设置受管项目。

该 CLI 为唯读且使用标准函式库。针对 `COVERAGE_COMPLETE` 会回传 `0`，针对 `INCOMPLETE` 回传 `1`，若纪录无效或发生读取错误则回传 `2`。每个结果皆明确声明编辑品质**未经认证**。它无法单凭验证杂凑值来侦测伪造的笔记、不实的适用性宣告、语意错误，或从错误文件产生的渲染输出。`execution_order_certified` 恒为 false：结构化纪录并无法证明时间先后顺序、诚实阅读、理解程度或科学正确性。

<a id="close-the-handoff-honestly"></a>
## 诚实完成交接

请回报已检查的候选版本、已完成的适用覆盖范围，以及具体的剩余限制。在来源或版面检查尚待完成期间，临时草稿仍可发挥作用；请勿将其标示为定稿、完全检查完成或符合期刊规定。完整的纪录在现有检验闸门下仍需要编辑与科学判断。任何相关的文字用字、引用文献、元数据、格式或相依项目的变更，都会使早先的验收失效：交付前请更新确切的候选版本并重新检查受影响的检验闸门。切勿因为这「只是初稿」而推迟这些检查，也不要将无关的全套套件检查强加于有界限的工作上。
