<a id="modes-and-lifecycle-stages"></a>
## 模式与生命周期阶段

对于有明确边界的文字工作，请使用轻量模式。对于持续的稿件整合、附随成果协同处理或发布认证，请使用受管项目模式。既有的受管项目会为局部编辑提供授权与决定；但不会扩大原本要求的审查范围。

除章节发展外，亦应辨识以下出版状态：探索性草稿、完整内部草稿、初次投稿、修订后重投、已接受稿件以及校样。随着状态推进，应缩小介入范围。在校样阶段，仅进行为确保准确性、排版制作或符合发表园地规范所必需的授权更正；未经明确许可，切勿重新更动已定案的结构或文风。

应区分三种时间轴：

- **写作顺序：** 作者撰写各章节的先后顺序
- **证据依赖性：** 后续的分析会限制前期的架构设定与后续的摘要总结
- **审查成熟度：** 发展阶段、实质阶段、整合阶段与投稿阶段

切勿将某个章节标记为永久完成。请将其标记为相对于特定已指名证据状态或发布候选版本的最新状态。

将 [execution-and-acceptance.md](execution-and-acceptance.md) 中的阶段核检表用于写作计划、编辑后检核、章节结尾检核以及四轮审查的证据检验。请重复使用同一份项目纪录；核检表应随任务而变动，而非随对话阶段变动。

对于未宣告其他顺序的传统实证论文，请遵循：研究定位 → 延伸证据大纲 → Introduction → 研究脉络 → Methods → Results → Discussion/limitations → Conclusion → 重建 Abstract。若有适用的不同文类或作者要求，请依其规定；章节编号与六大标题并非通用要求。补充材料应与 Methods 及 Results 同步撰写，并在整合阶段进行比对一致化，而非事后才草率补充。

在依发表园地进行大纲拟定或格式设定前，应建立或重复使用 [overlay-contract.md](overlay-contract.md) 中的发表园地设定档。应将科学问题／贡献与期刊方向及读者群的比对，与论文类型、特定阶段格式及文风的检核分开进行。处理范围相符并非新颖性或获接受的证据；两者不合是作者应做的决定，而非擅自更改研究的授权。在整合阶段，应对照现行的官方来源重新检核受影响的规范，而非仅依赖已发表的范例。

<a id="scope-and-check-depth"></a>
## 处理范围与检核深度

沿着四个独立轴向进行路径导向：**行动**（例如文法更正与科学审查的区别）、**文本处理范围**、**变更影响**，以及**验证深度／资料来源可用性**。整份文件的标点符号编修并不等同于完整的科学审查；单一句子中的指标变更可能就需要跨文件检核。

在各处理范围均应采用通用核心原则：确认已获认可的来源与授权、保留原意、检验相关的读者功能与主张界线、保持术语／比较的易读易解性，并检查确切的候选文本。仅在适用之处增加下列检核：

| 要求的单元 | 附加检核 | 切勿推论出 |
|---|---|---|
| 句子或纯文法编辑 | 文法修复、科学意涵未变更、局部指涉与符号表示 | 有权重构论点或为引文背书认证 |
| 段落 | 功能、主张与证据关系、意涵、前置条件、局部术语、前后文脉络 | 全文稽核或必须有结尾口号标语 |
| 小节 | 段落角色与顺序、缺失／重复的功能、相关图表／数据、累积实质回答 | 每一张图表都必须能独立证明整个研究问题 |
| 章节 | 小节之间的连结、章节目的与研究问题涵盖范围、方法／发现／诠释的配置、结尾盲点检核 | 对无关章节进行全面审查 |
| 整篇稿件 | 缺口–问题–方法–结果–诠释–结论链；摘要、术语、文献参照、数据、视觉图表 | 验证无法取得的原始证据或排除在外的随附文件 |
| 投稿文件 | 所选稿件、补充材料、回复意见与交付标的；承诺事项、标签、编号、稳定行号参照、修订标记／干净状态、完稿呈现 | 未选取或未检查之文件的备妥就绪状态 |

实质的局部审查会检核支持该局部主张的文献引用与数据。纯表面编辑则保留既有且未变更的佐证；若发现重大的实质错误应予标记，切勿擅自捏造修复方案、暗中扩大为执行模型，或声称已完成全面稽核。当缺乏脉络或资料来源时，应将可用的语言编辑与未核实的科学断言明确区分开来。

完成时，应将涵盖范围回报为：已检核、不适用、超出所要求的处理范围，或资料来源无法取得／未核实。局部的检核在处理范围内可能已属完整，但这并不代表整篇稿件均已备妥就绪。

<a id="reader-function-mapping"></a>
## 读者功能对应

在套用结构规则前，应先将实际章节对应至读者功能。

| 读者功能 | 实证论文 | 文献综述或综合分析 | 架构或方法论文 | 理论或概念论文 |
|---|---|---|---|---|
| 问题与缺口 | 绪论 | 绪论 | 需求与限制 | 问题与概念缺口 |
| 证据来源 | 研究脉络与资料 | 检索与筛选 | 需求与输入 | 既有理论或前提 |
| 分析流程 | 方法 | 综合分析方法 | 架构或演算法 | 论证或推导 |
| 主要贡献 | 结果 | 证据综合分析 | 验证或应用 | 命题或意涵 |
| 诠释 | 讨论 | 讨论 | 评估与意涵 | 边界条件 |
| 最终综合结论 | 结论 | 结论 | 结论 | 结论 |

当特定文类以不同方式提供相同功能时，请勿强制要求使用诸如 `Study Area`、`Methods` 或 `Results` 等标题。

<a id="review-maturity"></a>
## 审查成熟度

- **发展阶段：** 检验缺口、目的、架构、缺失功能与方法可行性。
- **实质阶段：** 检验证据对齐度、方法完整性、技术精准度、术语与图表。
- **整合阶段：** 检验跨章节传递、诠释、研究限制、摘要总结以及剩余阻碍。
- **投稿阶段：** 检验确切文件、元数据、参考文献、格式编排、完稿呈现与发表园地规范。

对于修订后重投，应将审稿者的每项要求对应至变更后的证据与回复产物。对于已接受稿件与校样，应将作者名列、结果、方程式、文献引用与制作端元数据视为受保护的高风险栏位。

审查成熟度并不等同于章节顺序。若 Results 变更了获得支持的主张，请在整合阶段重新检视 Introduction。

<a id="stage-gates"></a>
## 阶段关卡

<a id="project-and-outline-gate"></a>
### 项目与大纲关卡

应确认进行中的项目、资料来源、原型、目标读者、缺口、研究目的或问题、产出、贡献以及非主张事项。确保每个规划的研究问题都具备合理的证据途径。

应将延伸大纲建构为证据计划，而非仅是标题列表。针对各章节与规划的段落，应记录其读者功能、核心主张或问题、获授权的证据、推论界线，以及通往下一单元的衔接桥梁。在开始撰写散文草稿前，应由上而下（从缺口到贡献）以及由下而上（从现有证据到获支持的主张）检验大纲。

对于新草稿，应使该计划呈现为一系列规划的段落主题句，各主题句均附有相应的证据位置与必要的限定条件。在不含佐证细节的情况下通读该序列：它应能说明研究的推展历程，而非仅仅列出主题名称。对于缺乏佐证的发现，应标记为证据需求，而非已确立的结果。应采用该文类的读者功能，切勿将实证标题强加于概念性或理论性论文之上。

对于既有草稿，应撷取所要求章节的实际开头句，并注明各段落所履行的功能，借此进行逆向大纲分析。若开头句隐匿或误述了重点，应记录该不一致之处，而非暗中以理想化的摘要取代。应检核是否有功能缺失或重复、过早引入细节以及缺乏支撑的转折；并针对受影响的最小幅度段落进行修复。纯文法编辑不会触发章节的逆向大纲分析，且这两项操作皆不需要建立新的项目文件。

<a id="paragraph-and-section-drafting-gate"></a>
### 段落与章节撰写关卡

起草每个段落时，应依循五部契约：功能、主张、证据、开展与衔接桥梁。应于局部范围并结合可取得的相邻文本进行检核。对于小节／章节的工作，亦应依序通读主题句。在完成最终重写后，套用适当的确切候选文本检核；后续任何字词变更都会使受影响的检核失效。一个章节并非仅因所有规划段落皆已存在就代表处于最新状态；其各段落必须构成一个累积推进的论点，且不含重复的功能、孤立无援的证据或缺乏支撑的转折。

<a id="context-and-methods-gate"></a>
### 脉络与方法关卡

追溯资料或前提：从来源经过准备、测量、模型或分析、诊断以至产出。应将具可重复性的程序，与脉络描述及后续诠释明确分开。

<a id="results-gate"></a>
### 结果关卡

从已验证的产出建构研究发现。针对每项比较，应确认参照群组、情境、环境设定或时间点，回报必要的结果，然后说明观察到的模式对研究目的或问题所代表的意义。单纯的数据并非实质的回答。应在段落或小节的功能有所需要时加入诠释，而非在每张图表后都加上例行公事般的结尾句。暂时移除 SQ/RQ 标签：剩余的陈述仍必须具备回答问题的实质内容。Results 可描述分析直接支持的分解结构或关联性。基于文献的解释、未经测试的机制、替代解释以及政策意涵应置于 Discussion 中。应找出未产生任何回报结果的孤立方法，以及未描述任何方法的孤立结果。

<a id="discussion-gate"></a>
### 讨论关卡

明确区分直接发现、获支持的机制、诠释、替代解释、意涵与推测。说明各项研究限制如何改变推论或通则化能力。

<a id="conclusion-and-summary-gate"></a>
### 结论与摘要关卡

综合现有证据；切勿直接复制前期的摘要。保留研究任务与处理范围。切勿引入新证据，亦不可暗中将比较升格为验证。

<a id="companion-and-release-gate"></a>
### 随附资料与发布关卡

同步检查补充文件、图表、表格、元数据、封面／附随资料与储存库声明。检查确切的使用中文件，若仍存在必要证据缺失或高严重度问题，应阻挡发布。

<a id="top-to-bottom-integration-gate"></a>
### 全文由上而下整合关卡

在所有主要章节皆已齐备后，以四个截然不同的通次审查确切的稿件：论点与结构；证据与处理范围；学术散文文风；交付完整性。在散文文风通次中，审查术语、缩写使用、字面与语意重复、陈腔滥调、句子与段落开头、主词连贯性、旧到新信息流以及衔接转折。每当散文编辑变更了科学意涵或主张处理范围时，必须重新执行受影响的先前通次。

<a id="chapter-closure-blind-spot-check"></a>
## 章节结尾盲点检核

在每次章节完成或进行实质章节修订时，在常规撰写检核之后，即使未出现明显问题，亦应重新审视该章的推论过程。执行的时机是强制的；诊断内容则取决于实际的研究设计、主张、资料来源以及所要求的处理范围。仅针对标点符号的通次并不等同于章节完成或实质审查。

从章节指南与研究设计转接器中挑选适用的问题：

- Introduction/脉络：所选案例与实际证据的处理范围是否符合承诺的研究任务？前置条件是否安排在相依设定之前，以及选样是否被误认为具代表性？
- Methods：来源、应用假设与评估是否界线分明？所描述的操作能否在没有隐含的移转、相依性或聚合假设下，支持所承诺的推论？
- Results：组成成分、分母、操作顺序或比较条件是否可能改变其意涵？因果解释是否获得规则或相关性以外的充分支持？
- Discussion/研究限制：在延伸推展中究竟有何者保持稳定，以及各项限制缩减了哪项推论？狭隘的指标是否被泛化为更广泛的构念？
- Conclusion/Abstract：内容压缩是否遗漏了条件、比较对象、主体、处理范围或限定语句，或是夸大了因果／验证强度？

应灵活调整而非生搬硬套范例：质性研究可能需要反例与可转移性检核；理论研究需要前提与反例检核；综合分析则需要涵盖率与异质性检核。仅重新检视相关的相依关系；缺乏证据并不等于无效的证明。记录实质发现以及已检核／不适用／超出处理范围／未核实的界线，无须为每个段落都建立流水帐。这并非保证已找出所有未知的未知。

<a id="change-impact-classes"></a>
## 变更影响等级

| 等级 | 范例 | 最低限度重新检核 |
|---|---|---|
| A: 语意契约 | 缺口、子问题、产出、任务动词、贡献 | 整体证据链；标题、摘要、亮点、结论、投稿摘要 |
| B: 证据或方法 | 样本、模型、分析、数据、图表、研究限制 | 来源以及受影响的 Methods、Results、诠释、视觉图表、补充材料、摘要总结 |
| C: 元数据 | 作者、角色、资助、所属机构、声明事项 | 载有这些项目的各项投稿产物中受影响的栏位 |
| D: 表面修饰 | 文法、标点符号、格式排版 | 局部语意差异、受保护脉络、完稿呈现 |

当单一编辑包含多个等级时，应套用最高影响等级的重新检核，加上各项产物特定的检核。

应依据相依性触发条件而非文件大小，来扩大局部检核的范围：

- 定义／缩写变更 → 受影响的用法与独立阅读的产物；
- 指标、分母、单位或数值 → 受影响的绘图、图说标题、结果、诠释与摘要总结；
- 方法／机制变更 → 实作／设计描述、证据、假设与推论界线；
- 研究问题或核心结论变更 → 完整的证据链与摘要总结；
- 文献引用增删或主张变更 → 来源佐证、其他用法、参考文献清单条目；
- 仅文法／标点符号 → 局部语意差异与相关格式检核。

若触发的相依关系超出写入授权范围，应在许可情况下进行检视并回报所需变更；切勿暗中编辑。当相关输入未变更时，请重复使用现有的已验证证据。
