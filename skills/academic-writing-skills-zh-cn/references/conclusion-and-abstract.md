<a id="conclusion"></a>
## 结论

综合归纳 **该研究做了什么 → 确立了什么 → 增添了什么贡献以及适用于何处**。采用如 “This study examined…” 的直接开头是有效的。当 “aims to” 能准确陈述目的时即可使用；请以适当的时态报告已完成的工作。在表明该研究身分之前，毋须重新撰写包含重要性–缺口–目的的引言。

陈述方法与研究任务、研究对象或系统，以及相关的地点、时间或分析处理范围。仅提及某个架构的名称并不等于解释了它是用来调查什么。请保留实际的任务动词，并区分开发方法、示范应用、比较群组以及验证预测。

在为实质总结修订挑选句子前，先从当前的引言、已核准的大纲与作者需求中找回研究的主体定位。在现有的写作计划中，区分**目标**（该研究试图增进何种理解或改善何种决策）与用于解决该目标的**工作**。仅在研究设计支持之处，才具名指出被研究的实体、比较基准、维度以及总体/子群组层级。切勿将方法、模型比较、招募平台或示范区域变更为替代目标。未列出编号问题的论文仍有其研究目的；切勿为了表达目的而凭空捏造次要问题（SQs）或固定数量的句子。

遵循所要求的段落功能。若开头段落说明了该研究做了什么，而后续段落综合归纳研究发现，请保持这两种角色的区隔。保留原本已清晰的开头与可用的作者语句；仅修补缺失的关联或处理范围。教授过去的范例提供的是风格参考，而非当前的样本数量、群组名称或已核准的措辞。

区分招募族群、研究地点、背景情境与示范案例的角色。更正地理描述时，切勿删除科学目的，亦不可将已知边界隐藏在 “study context.” 之后。若仅在总体层面检验测量品质，而子群组工作仅涵盖分布与关系，则不可将每个总体维度扩展至每个子群组。请参阅 [evidence-context case 12](evidence-context-cases.md#12-research-identity-before-sentence-compression)
以取得假设性范例与维持不变的对照组。

依据研究问题或分析顺序来综合归纳答案，而非逐一重述每张图表。保留主要对比、比较基准、方向以及对语意至关重要的任何条件。描述机制时，其强度仅限于分析所支持的程度。以主要的 Results 作为证据基础，并以 Discussion 进行限制与限定；切勿仅因其听起来更广泛，就引入新发现或将延伸分析提升为头条标题。

结尾应提出由这些答案支持的具体贡献、意涵或应用边界。政策可行性与负担能力的主张需要相关证据；单纯比较损失并不能确立这些主张。不强制要求固定的段落数量。切勿照抄摘要、强加宏大的政策建议，或将可用选项的数量等同于其实际成效。

<a id="abstract-identity-and-information-functions"></a>
## 摘要主体定位与信息功能

依据已稳定的稿件重新建构摘要，而非依据过时的概要。使读者在没有图表、内部代码或起草历程的情况下仍能理解该研究。请依据体裁与已核实的发表管道限制，以适当的密度提供以下信息功能：

| 功能 | 读者应了解的内容 |
|---|---|
| 问题或科学需求 | 哪种理解或决策至关重要，以及缺失了哪些相关知识。 |
| 目的 | 本研究调查、开发、估计、比较或确立了什么。 |
| 方法及其角色 | 哪种方法产生了证据，以及该方法实际发挥了什么作用。避免列出没有说明目的的技术名称。 |
| 研究对象与处理范围 | 研究对象为何，以及解读该答案所需的地点、族群、资料集、时间区间或设定环境。 |
| 主要发现 | 有支持依据的实质答案、具名比较的项目、方向或幅度，以及关键的限定条件。 |
| 贡献与边界 | 增添了何种新理解，以及该主张得以成立的处理范围。 |

这些是信息功能，而非六个强制性的区块或固定的句子数量。自然流畅时可将其合并，或遵循已核实的结构化摘要格式。研究背景并不必然是地理试验场域：它可以是实质研究对象、选定的样本、理论领域或评估资料集。切勿仅因使用了某个案例进行示范，就主张具代表性或通用性。

在首次相关使用处解释必要的专门术语，即使正文稿件中已对其进行定义。当目标读者群理解时，请保留标准术语；替换不必要的内部简称。平实的描述（例如 “losses after insurance payouts”）可伴随已定义的产出结果出现，而不改变其意义。保留理解主要发现所需的比较基准与事件/时期条件。

切勿为了填补范本而捏造最佳化目标、代理人动机、回馈机制或数值结果。应从当前的引言与已接受的研究定位中推导科学动机。仅在无法从这些来源解决重大缺口时才提出询问；切勿在每次改写前都要求使用者重复已提供的 “why”。

<a id="rules-versus-preferences"></a>
## 规则对比偏好

这些功能并未衍生出通用的字数或句数上限、单一段落要求、固定开头、强制置中的研究区域、禁用原始数值、禁用连接词或禁用标点符号的规定。请将已核实的发表管道要求与明确的项目/指导教授偏好作为已分类的叠加层套用。当数值能增进主要答案的清晰度且有证据支持时，请使用数值；即使省略了数值，仍应保留有意义的比较。

组合另一个摘要写作技能时，请使用 [overlay-contract.md](overlay-contract.md) 对其规则进行分类。过往的六部分范本或禁用词清单并非通用权威；切勿引入要求提出缺乏支持依据的主张或与使用中项目相冲突的指示。字数限制仅针对已确认的当前要求进行计算。可观察到的陈腔滥调是一种可读性诊断指标，绝不能作为 AI 撰写的证明。

<a id="compression-and-standalone-checks"></a>
## 压缩与独立阅读检查

在缩短任一总结后，将其与当前的证据图谱进行对照。检查精简过程中是否遗漏了分母、母体、基准线、时间范围、仅适用于模型的限定条件或推论界线。确保描述性相似性未被写成等价关系、模型规则未被写成已证实的因果关系，且具条件限制的指标未被写成整体的保护或脆弱性。

单独阅读精确的摘要。广泛领域的读者是否能说明其方法、研究任务、研究对象、相关处理范围、主要答案与贡献？单独阅读结论：它是否综合归纳了实际研究，而非提出新的主张？在其他部分发生重大变更后，请重新检查这两部分。使用 [lifecycle-and-routing.md](lifecycle-and-routing.md) 进行章节结尾检查，并使用 [prose-and-citation-editing.md](prose-and-citation-editing.md) 确保平实的学术句法。

针对说明研究主体定位的段落，首先仅从已完成的散文中改述作者试图理解什么、为达成该目标做了什么，以及谁或何者在哪些维度与层级上被进行比较。接着将该解读与权威规划进行对照。一连串正确的 “we first / we then” 步骤、重复的 “comparison” 子句或模棱两可的巢状 “between” 片语，仍可能遗失研究目的或层次架构。请修复此种遗失，而非删除能使比较保持清晰的技术性重复。移除 SQ 标签绝不能同时移除其关联性。若缺少权威依据，将限制评判结论；切勿为了填补开头而凭空捏造目标。此项功能性检查隶属于既有的读者演练流程，而非第二套检核表，亦非未来助手将会遵循的证明。
