# 审查意见回复工作流程

此参考资料适用于申辩信（rebuttal letters）与审查意见回复文件。

<a id="core-rule"></a>
## 核心规则

唯有直接回答审查意见的疑虑，并指明稿件中有明确可见的修改，或是针对未依要求修改提供具证据支持的理由时，回复才算完整。回复文件可包含有助于审查人理解、但无须纳入稿件或补充材料（Supporting Material）的分析与实作细节。

<a id="build-a-comment-ledger-first"></a>
## 先建立审查意见清单

在起草文字之前追踪每则审查意见：

```markdown
| ID | Reviewer Comment | Anchor Text | Response Strategy | Manuscript Change | Status |
|---|---|---|---|---|---|
| R1.1 | ... | Section 3.1 | revise model; Figure R1 | revised method | RESOLVED |
```

逐字保留审查人的原始意见。将包含多个部分的意见拆解为具体问题，以免修饰流畅的段落掩盖了未回答的部分。在回复策略栏位内记录子问题与证据，或在复杂修改有需要时新增选填栏位；切勿建立第二套不相容的清单结构。

若先前的某项疑虑已不再适用，请针对该子问题记录原因，并独立检核其余问题。切勿仅因其中一部分已被取代，就删除包含多个问题的讨论串。单纯的回复、查询 DOI 或产生的算绘图，仅能证明已执行该动作，并不代表已完成分析、具备主张层级的支持或已完成视觉检查。

请遵循稿件状态的状态约定：`OPEN` 代表未解决的工作，`RESOLVED` 代表已完成且已核实的回复，而 `WAIVED` 仅限于已指明的权威接受残留问题与风险时使用。

针对每项疑虑，在此清单中套用 [comment-scoped-revision.md](comment-scoped-revision.md#test-concern-closure-separately-from-edit-completion) 中的结案评估：原始选定措辞／版本、实际问题、当前答案与已定位的证据，加上已处理／部分处理／未解决／无法核实并附带理由。这些评估并不会取代前述的状态。请务必核实答案本身，而非仅确认答应修改的文句已存在；汇总合并的回复不能用来结案某个仍未回答的独立子问题。请保留当前工作中的措辞。

将所需工作归类为下列一或多项：

- 厘清既有的方法或结果；
- 修正错误或含糊不清的规格说明；
- 新增或重新执行分析；
- 补充证据或引用文献；
- 修改诠释、处理范围或限制；
- 说明具体理由以婉拒或推迟某项要求。

<a id="distinguish-response-states-and-advisor-handoffs"></a>
## 区分回复状态与指导教授交接流程

策略、呈交指导教授的工作草稿，以及最终呈交审查人的回复，这三者应保持明确区分。策略须指明预计采取的行动与所需证据。工作草稿可在所有修改尚未齐备前先行铺陈预定论点，但必须标示待进行的分析、修改与定位点；拟议的措辞不能作为已完成的证据。最终回复仅报告已核实的工作或具证据支持的不作修改理由。在该疑虑确实获得处理并经核实之前，清单状态应维持为 `OPEN`。

当研究室提供的工作流程要求「先回复后由指导教授审查」时，请遵循其交接顺序：审查意见清单与简要策略 → 指导教授同意 → 回复工作草稿 → 指导教授审查 → 经授权的稿件／补充材料修改 → 最终答应事项与产出物对照及定位点核对。这是可选的项目工作流程，并非要求在编辑前必须取得指导教授核准的普遍通则。策略的获准本身并不代表已授权可执行新分析或外部行动。若范本偏好工作草稿使用现在式或过去式，请明确标注尚未完成的内容，切勿将未执行的实验呈现为已完成。

<a id="distinguish-revision-provenance-from-topical-relevance"></a>
## 区分修改出处来源与主题关联性

在新增标注审查人来源的边页注解或宣告稿件修改之前，请将实际生效的修改文字与当初实际投稿的稿件或其他明确约定的修改基准进行比对。请阅读实际生效的修改文字（保留的文字加上新插入的文字），切勿将已删除或移出的文字串接进来。

将每段候选文本分类为未变更、新插入、已替换、已移动、纯格式变更或已删除。仅针对确实因回应该审查人而修改的文字、图表展示或位置，新增标示审查人来源的标签。边页标签是用来记录修改的出处来源，并非主题索引。未变更的原始文本或许可支持回复论点，但应维持不加标签，并在清单中记录为 `existing text; no manuscript change`。回复可引导审查人参阅该既有段落，但不可声称该处有修改。

若审查人对未变更的措辞感到困惑，请判定既有段落是否已回答该疑虑。若是，请进行解释并加以引用；若否，请进行幅度最小但充分的修改，并将标签锚定在该修改处，而非整个周边段落。当单一修改同时回应多则意见时，请使用一个注解方块列出适用的审查人 ID，切勿在相邻位置重复放置标签。

对于基于模型或计算的研究方法，请将定义与衍生量，与经验输入值、校准参数、文献支持或分析者自选的假设，以及演算法或更新规则明确区分开来。对于其他研究设计，请依其实际的方法学功能对段落进行分类，例如抽样、测量、介入措施、程序、编码或分析。切勿仅因某个定义或衍生结果与假设并列，就将其视为假设。请让回复主张、相关清单项目、修订追踪（Track Changes）与审查人标签，与实际变更的功能保持一致。仅在修改确实需要此项区分时，才在清单中新增选填的来源或出处栏位。

<a id="distinguish-navigation-from-the-full-answer"></a>
## 区分导引说明与完整回答

审查人有时会在列出编号的主要意见之前，先提供高层次的统整观点。

- 高层次的回复应保持精简：确认问题所在、陈述主要处置，并引导读者参阅下方的详细回复。
- 将第一个完整的解释、设计、证据与结果，放在最早提出该问题的详细意见下方。
- 将审查人的每条详细意见视为可独立阅读。后续相关的回复必须包含足够的局部脉络、关键结果及其意涵，以回答该项特定的疑虑；此处可回指前文的完整的共用设计、图或表，无须重复列出该证据。
- 切勿让前面的详细回复仰赖后面的审查意见回复。指向后文的参照（forward reference）仅适用于前言导引区块。

<a id="build-opening-and-closing-responses"></a>
## 建立开篇与结尾回复

在开篇的修改摘要中，每一点应赋予单一功能。请将研究或模型的变更、补充分析、文件修订及图表展示更新分别列出，切勿在多个标题下重复提及同一项修改。若回复范本要求提供导引信息，可指明是哪位审查人或编辑促成了该项变更，但请将完整证据保留在相关的详细意见下方。

将审查人结尾的总体评估视为独立的意见。当该意见无须采取额外行动时，简要致意确认即可，切勿重复前述的修改摘要或已列出的证据。

<a id="draft-a-major-response-in-this-order"></a>
## 依此顺序起草主要回复

在维持此推理顺序的前提下，使用最少必要段落数：

1. **肯定并理解审查意见的疑虑。** 简要说明该意见为何指出了重要问题或契机。
2. **陈述修改内容与原因。** 指出有所变更的方法、模型设定、分析或诠释。在修正规格时，请说明其不一致之处，切勿让人觉得微调参数纯粹是为了取得属意的结果。
3. **说明执行的程序。** 提供足够细节以供审查人评估该工作，包含在论文中无须赘述的重要细节。
4. **陈述工作处理范围。** 若修改需要完整重跑模型、重新产制图表或重复进行分析，请明确说明。
5. **呈现已核实的证据。** 在列出数据之前，先提供诠释该数据所需的统计特性与比较基准。在相关处提供分母、参考值、不确定性摘要或对齐的设定。
6. **诠释结果。** 切勿在报告数据或描述图表后便戛然而止。请说明何者改变、何者维持稳定，以及该证据如何回应审查意见的疑虑。
7. **指明稿件修改处。** 列出实际修改的章节、图、表或补充材料项目。唯有在指定的审阅版稿件及其排版格式底定后，方可使用最终行号。
8. **在重大限制存在时说明残留边界。** 说明本研究仍未涵盖哪些层面并说明原因。切勿仅以空洞的 “no.” 作答。

开篇的肯定与理解应保持简短。切勿在说明作者做了哪些修改或回复为何采取不同立场之前，长篇累牍地转述审查人的意见。

若是简短的厘清或错字更正，请将此流程压缩为一至两句话，切勿捏造不必要的细节。

当包含多个部分的意见同时需要条件说明（qualification）与采取行动时，请在转移重点之前先完整回答需说明之处。接着使用明确的转折词，例如 “However, we agree...” 或 “Following the reviewer’s suggestion...,”，以指明作者接受的部分以及所执行的具体分析或修改。如此可在谨慎辩明之后突显具体的回应行动，但绝不可因此转移焦点、取代或遗漏对该意见第一部分的回答。

<a id="match-response-length-to-the-scientific-weight"></a>
## 让回复篇幅与科学份量相称

若审查意见引发了模型重新设计、采用新资料集、新增分析或完整重跑，其回复的完整程度应至少不下于该审查意见，且篇幅通常应相当。请将篇幅长短视为警讯（提醒可能遗漏了原因、实作细节、证据或意涵），绝不可作为重复内容或充填无关字句的理由。请在不让回复变成第二个研究方法章节的前提下，突显所付出的额外工作。次要的编辑性意见无须刻意扩充篇幅。

针对重大的模型或分析变更，若仅供回复用的表格或图形能让审查人迅速验证效果，可考虑采用。唯有在该图表能直接分离出受到质疑的因素，且立基于当前模型与证据时，方可使用。切勿纯粹为了让回复看似内容充实，就纳入混杂多个同时变更的比较，或是依赖过时的产出结果。

<a id="present-numbers-without-creating-a-new-vulnerability"></a>
## 呈现数据且不制造新的漏洞

- 当读者需要分母或比较基准值以进行诠释时，为每个绝对误差或计数提供该分母或比较基准值。
- 在呈现可能造成误导的指标之前，先说明资料覆盖率、分析单位、地理尺度不相符或其他统计限制。
- 对观察到的数值使用中性描述。避免给出 “the model fails,”、“weak agreement,” 或 “overall overestimation” 等定论，除非该结论具备证据支持且属必要。
- 指出具科学相关性的讯号（无论有利或不利），但不可做出超出证据支持的倡议或主张。
- 无须向专家解释标准指标，除非其定义为本研究特有；应改为解释这些数值对本次分析代表的意义。
- 将绝对值诊断指标与标准化时间序列比较区分开来，并说明各自回答了哪个问题。
- 在陈述每项比较结果的同一个句子中指明比较基准。若读者必须自行推敲比较的基准设定、组别、时间或情境，则像是 `higher`、`lower`、`increased`、`decreased`、`remained` 或 `unchanged` 等词汇便是不完整的。
- 切勿仅从参数值、分布、规则或模型设定之间的敏感度比较，推论某个情境相对于另一情境的效果。不同设定之间的差异并不能证明个别情境对比的效果，除非该对比经过直接计算。
- 报告图表的第一个数值结果时即应引用相关图表。挑选能回答审查意见的最少必要数值组合即可，无须逐一叙述表格中的每个储存格。

<a id="explain-sensitivity-and-robustness-results"></a>
## 解释敏感度与稳健性结果

敏感度分析的回复必须指明：

- 受到质疑的假设；
- 以浅白语言说明的当前设定与替代方案；
- 维持不变的条件；
- 用于判定敏感度的结果指标；
- 结果的方向与量级；
- 相关诠释是否有所改变；
- 当涉及规格选择争议时，正式模型中采用了哪种设定，以及该选择的独立依据；以及
- 该结果在何处报告。

将每项敏感度回复依「**原因 → 内容 → 比较 → 结果 → 意涵**」来组织。若审查人明确要求进行检定，请说明所选设计如何回应此要求。若审查人未明确要求检定，请先解释受到质疑的假设为何可能影响报告的结果，以及为何额外的检定具有参考价值。接着指出进行比较的确切设定或组别，以及用于判定影响的结果指标。绝不可在未说明目的的情况下引入实验。

在结果与诠释部分，应以明确的证据链作结：说明估计量级是否改变，并指出具体有哪些模式、诠释或结论改变或维持不变。切勿仅写 `the conclusion was unchanged`；请陈述结论本身。

当检定或审查意见提出规格选择问题时，请另行加入一项决策声明，指明正式模型中所采用的设定及其既有确立的依据，例如资料、校准、理论、研究设计或预先指定的建模选择。若发现替代设定不改变主要结论，这证明的是稳健性，其本身并不能用来挑选或验证基准设定。若缺乏独立的选择依据，请说明敏感度分析无法决定应采用何种设定。切勿在看到敏感度分析结果后，才事后捏造新的经验、理论或实务理由。若该分析纯粹为了检验稳健性且不涉及规格决策争议，切勿强加模型选择的主张。

在实际受测的层次上指明比较的设定。在单因素实验中，请使用确切的基准值、区间、分布、规则或序列。将 `original model setting` 与 `revised model setting` 等标签，保留给各版本皆有明确描述的局部定义全模型比较。切勿仅因同一词组在单因素敏感度检定中显得含糊，就全面替换已具备定义的全模型标签。

当需要做出最终模型决策时，请将其置于结果及其意涵之后，并在指明稿件或补充材料的安放处之前。让句子自然承接前述证据，切勿在每则回复后都附上千篇一律的套版转折语。当单一回复汇总了数个敏感度实验时，在每个实验皆获得各自的局部结果与意涵后，可使用句结尾语列出所有最终设定及其既有依据。个别的详细回复仍必须陈述任何局部相关的决策，以便每则意见都能被独立阅读。

在呈现证据之前，请于回复内文中先提供诠释图表所需的信息。这包含比较基准、变更的因素、在重要时标明比较的次数、不确定性摘要，以及正负差异所代表的意义。表格注记应维持精简，且仅用于紧凑而自成一体（self-contained）的细节；切勿将实验设计、比较逻辑或实质诠释隐藏在注记之中。

在报告图表中的第一个数值之前，先加上一句直接陈述的话，说明该图表比较了什么、报告了哪些结果指标，以及数值如何汇整。标题应明确点出结果指标与比较基准；像是 “sensitivity results” 或 “comparison” 的标签是不够的。请使用内文（而非图表说明或注记）来解释为何进行这项比较以及结果代表什么意义。表格注记应严格限制于阅读各项目所需之信息，例如单位、分母、摘要统计量、不确定性标记法或正负号的意涵。

依审查人的问题选择证据呈现格式。若要紧凑比较终点数值或多项精确对应关系，请使用表格；若疑虑涉及顺序、时序、轨迹或路径相依性，请使用时间序列图。对于相同的数值，除非图与表各自回答了该意见的不同部分，否则切勿同时纳入两者。

回复内文与图说明应保持区隔。在内文中，用一句话引导出科学比较、报告结果，并针对审查人的疑虑解释其意涵。除非某种视觉编码本身就是论点的一部分，否则切勿引导读者逐一检视子图代号、颜色、线条样式、标记或区间带。子图配置、视觉编码、样本数或执行次数以及不确定性定义，应放在图说明或图例中。图说明结构与术语应与稿件既有风格相符，切勿自创一套仅用于回复的图说明风格。图说明应解释如何读图；内文则应解释该图在科学层面呈现了什么。

将所采纳的基准模型规格与敏感度检验程序明确区分。纯粹检验稳健性的敏感度检定若未改变模型规格或主要诠释，切勿将其作为所采纳模型研究方法的一环来呈现。研究方法章节应聚焦于所采纳的规格、校准与假设。当敏感度结果对一般读者甚为重要时，在相关结果段落的末尾加上一至两句话说明其影响。当延伸证据置于补充材料时，自该段落引导读者参阅补充材料；其余情况则将证据保留在回复信中。请明确陈述所选的安放位置，切勿在所有位置重复相同的细节。

切勿使用内部实验 ID、未经解释的标签（例如 “higher” 或 “narrower,”），或审查人未曾见过的软件术语。请指出实际的参数区间、规则、分布或事件序列。

当有多则意见涉及同一个实验时，请在第一个实质提及处给出完整的设计与证据。后续的回复仍必须说明当前的局部目的、关键结果及针对该意见的具体意涵，但可引用先前的图或表来指涉共用的设计与完整证据。

<a id="separate-three-destinations"></a>
## 区分三个安放位置

每则回复皆应区分以下三者：

1. **仅限回复：** 回答审查人所需、但一般读者无须了解的诊断性证据、比较表格或实作细节。
2. **稿件正文：** 为了方法透明度、结果诠释或主要结论所必需的修改。
3. **补充材料：** 可重现性细节、延伸方法、完整技术结果或作者选择提供的研究工具。

正文表格与相关的补充材料表格应具备不同的读者功能。正文表格应承载跟随论文论点或模型所必需的信息，而补充表格则提供出处来源、实作细节或延伸证据。切勿仅为了显得有正面回应，就在两处重复列出相同的项目。

切勿纯粹为了显得乐于配合，就答应在稿件或补充材料中增补内容。在修改尚未实际完成前，切勿声称修改已经完成。在规划阶段，请使用未来式或明确标示拟议措辞。在最终回复信中，核实指定文件后，针对已完成的修改应使用过去式；现在式则可用于描述当前的证据或文件内容。

<a id="tone-and-vocabulary"></a>
## 语气与词汇

- 当审查意见带来了有意义的修改时，展现专业的谢意，但切勿以千篇一律的公式化句型作为每个段落的开头。
- 写作时请设想审查人虽理解论文的大致研究方向，但可能不清楚模型内部的运算顺序、项目特有术语或先前的起草历程。请在首次使用时解释每个必要的术语、比较与因果步骤，切勿预期审查人能自行拼凑理解。
- 开门见山给出答案，随后附上证据与稿件修改处。
- 使用稿件中已有的术语。当读者可能未曾见过某个缩写时，在该审查人回复章节中首次出现时加以定义。
- 立即定义本研究特有的术语；若有助于将其与既有既定术语区分开来，首次使用时请加上引号。
- 避免自创复合标签、诸如 “the revised design,” 的含糊参照，以及未加解释的内部简称。
- 偏好主词与动作明确的质朴语句。变换转折词，使相邻段落读起来不致像是断开的条列句或重复的 “We...” 陈述。
- 切勿夸大完成度、稳健性、验证程度或泛化能力。

起草完成后，请大声朗读完整的回复，或模拟一般口语朗读。请保持技术意涵精确，但若有任何句子听起来像是生硬拼凑而非研究者自然写就、需要反复回读才能理解，或是会让目标审查人困惑于其主词或比较对象为何，皆应予以修改。

<a id="revise-an-advisor-edited-response-draft"></a>
## 修改经指导教授审订的回复草稿

将最新经指导教授审订的文件视为工作基准。保留指导教授可用的修改，且仅变更被标注出的问题、经核实的事实相依处，或是上下文仍不清楚的措辞。切勿仅因较旧的草稿包含较多细节，就依据旧草稿重新建构回复。

针对有定锚的指导教授注解，在提出修复前，先使用 [comment-scoped-revision.md](comment-scoped-revision.md) 阅读其当前所选范围与完整讨论串。保留未被选中但可用的措辞；报告确切修改的句子以及超出该范围且有证据支持的相依变更。内部回复或标记为已解决是独立的动作，并非修改内文时的自动环节。

将三项产出物分开：呈交审查人的回复、稿件或补充材料中对应的修改，以及给指导教授的内部回复。给指导教授的内部回复请以精简的第一人称撰写，通常为一句以具体行动开头的话，例如 `I revised`、`I clarified` 或 `I added`。仅在指导教授提出疑问或表示困惑时，才解释原始意图。当指导教授提供写作策略时，简短致意该项建议并指明应用于何处。常规格式调整、确认事项与结尾意见仅需简短回复即可。

修改回复内文后，请重新阅读指导教授的注解并更新内部回复，使其准确描述实际进行的修改。当修改同时改变了比较、诠释、最终模型决策或文件安放位置时，切勿留下仅写着 `I clarified` 的过时回复。

<a id="disagreement-or-an-unimplemented-request"></a>
## 意见不一致或未采纳的要求

在有证据支持的前提下，表达不同意见是可接受的。请采用此结构：

1. 理解并肯定审查意见的疑虑；
2. 陈述证据、资料边界或学界惯例；
3. 解释所要求的实作方式为何站不住脚或不可行；
4. 在存在的情况下，提供最接近的有效分析或厘清说明；以及
5. 说明由此产生的限制或未来研究方向，但不可将其用作替代当前答案的托辞。

切勿在没有立论支持的情况下写入 “we respectfully disagree” 或 “this is outside scope”。切勿纯粹为了显得有正面回应，就加入无法被一致呈现的不完整机制。

<a id="contradictory-reviewer-requests"></a>
## 互相矛盾的审查意见要求

当审查人要求彼此不相容的修改时：

1. 在工作清单中明确标出冲突；
2. 优先考虑编辑的决定、期刊处理范围、研究证据与内部一致性，而非机械式地试图同时迎合双方要求；
3. 在两位审查人的回复中皆解释所选用的做法，使任一回复都不致显得忽略了另一方的疑虑；以及
4. 当冲突若不改变研究的科学处理范围就无法解决时，在投稿说明信（cover letter）中请求编辑指引。

<a id="formatted-response-documents"></a>
## 具格式排版的回复文件

当交付成果为 Word 格式的回复文件时：

- 逐字保留审查人意见及其原有文字颜色；
- 保留回复颜色、修订追踪、边页注解、版面设定以及研究室既定的范本；
- 一致地格式化仅供回复用的图表标签；
- 依最终首次引用的顺序，为仅供回复用的图表编号，随后一致地更新每处交互参照；
- 将参考文献保留在文件的既定位置；
- 在算绘产出后，核实跨页的意见回复区块、分页表格、图表说明、方程式与图表；以及
- 唯有在指定的稿件版本及其排版格式底定后，方可填入行号预留位置。

使用现有的 `docx` 或 Word-document 技能来执行修订追踪与 OOXML 操作。

<a id="promise-to-artifact-reconciliation"></a>
## 答应事项与产出物对照核对

进行修改套件检核时，请从双向进行检查：回复中答应的每项承诺，皆必须指向已实作且已核实的修改，或提出具充分理由的不修改说明；而稿件／补充材料中的每项实质修改，唯有在直接回应某项审查意见时，才应报告于该意见之下。切勿将每处编辑性改动都转化为新承诺、切勿在未变更的文本加上主题标签，亦不可默默将未兑现的承诺标记为已解决。当缺少必要的补充或分析时，请保留该未解决问题。写作审查并不代表已授权可重新执行模型。

追踪实际的安放位置与变更的功能。初始化、年度更新、决策门槛与执行机制各有不同；支持其中一项的证据不能用来确立另一项。请检查重要假设是否置于研究方法中，而非仅在研究限制中披露。支持制度论理的文献来源不能用来估计数值门槛。横断面调查证据无法验证同一个人随时间的年度变化。对于非机率样本，切勿将简单随机抽样的误差范围呈现为该样本已证明的精确度。请在重复执行所实际衡量的层次上描述其不确定性。

区分来源比较与直接验证。地理涵盖范围、抽样单位、纳入标准与分母必须相符或加以限定：每笔已理赔赔案的平均值不等于所有家户的平均值，且某区域的纪录不必然是模型建构领域内的观测值。请说明诊断指标实际评估的内容；切勿暗示记录了此项不符便全盘推翻每个组件，亦不可暗示模拟出的轨迹即为实际观察到的登记注册情况。

在重新调整图、表、章节或补充材料后，请依其用途逐一核实每处参照，包含子图代号、图表说明、清单、缩写选择以及相关的回复承诺。请与稿件中实际保留的术语保持一致；若某个缩写已被移除，切勿声称有使用该缩写。检查引用文献是否与所支持的子句及参考文献清单相符（包含作者与年份后缀）。在删除某篇参考文献前，请先检查其在其他地方的引用情况。新增引用文献必须具备主张层级的支持，而非仅凭标题相关或希望引用近期著作。

为回复定位点选择并记录算绘出的目标版本。依交付合约，该版本可能是干净版稿件，或是比对／标记版稿件；绝不可从 XML 段落计数推算行号，亦不可沿用其他版本或标记检视模式下的行号。在读取显示的行号前，请先冻结内文、版面设定、行号配置与显示模式。若分页发生变动，请重新检查受影响的范围，切勿认定微小修改不会产生影响。对于未编行号的补充材料，请引用其 Text／Figure／Table 项目编号；切勿套用正文行号或留下最终 XX/XXX 预留位置。当目标无法算绘时，请将定位点标记为未核实，切勿凭空猜测。

以获接受且经指导教授审订的基准为基础，衍生出修改后的回复。若要求提供干净版与比对版的回复版本，请将该基准清理干净，并将已核实的最终修订版本与之比对，同时保留审查人文字与必要标签。请检查实际生效的修改文字与算绘产出物，而非串接了删除／插入文字的草稿。在宣告整套投稿文件准备妥当之前，请确实报告已检查了哪些项目。

<a id="checks-after-a-model-or-evidence-revision"></a>
## 模型或证据修订后的检核事项

这些检核事项旨在解决当模型修订同时改变了数据与结果解释时常见的反复出错问题：

- **先锁定当前证据。** 指出每个结果背后的来源版本、配置与产出物。旧图表或已完成的实验不会仅因其标签仍与意见相符，就成为当前有效证据。
- **区分方向、量级与机制。** 某个组别可能仍维持较大比例的损失减少，但产生该减少过程的机制可能已改变。切勿将此概括为 “the conclusions are unchanged.”。请精准陈述何者维持不变、何者必须重新诠释。请区分绝对损失、百分比减少，以及相对于所得或其他分母的损失。
- **切勿将多项合并修订归因于单一因素。** 数次模型变更后的结果呈现的是其合并效果。若要主张是其中一项变更造成了差异，需要适当的控制比较或其他支持证据。决策规则所提示的机制，并不能自动视为对观察到的效应大小之测量解释。
- **将假设、校准与验证明确区分。** 文献或许可支持某个方向，但无法支持确切的区间或初始比率。请诚实标注建模者自行选定的数值。唯有存在校准程序与目标时，才称该数值为经校准，且切勿将同一个目标视为独立验证。门槛或指派机率本身并非观察到或实现的采纳率。
- **对齐比较群体与定义。** 检查地理区域、年份、家户组别、分母以及事件或政策定义。切勿在未解释差异的情况下，将某子群体的模型估计比率与全体人口基准进行比较。相对于绝对误差而言较小的带正负号误差可能反映了相互抵消，其本身并不能证明集中趋势准确。
- **对模型涵盖范围的主张保持严谨克制。** 新增某项属性并不意味着模型涵盖了所有相关的危害、行为、制度或定价关系。请解释哪些计算确实使用了该属性，以及哪些相关性仍未呈现。
- **核对事实，而非仅润饰措辞。** 对照原始纪录核实样本数与特定分析的排除项目。切勿纯粹为了表面一致而强行让不同的有效样本数一致，亦不可将未核实的修正描述为已完成。
- **阅读实际生效的修改文字。** 检视修订追踪时，请将保留与插入的文字与删除的文字区分开来。切勿将两个版本串接在一起，并把由此产生的重复内容当成当前内文来诊断。若因现行文件无法读取而使用了存档副本，请明确指明。
- **避免不必要的扩充。** 赋予摘要要点不同的功能，例如模型变更、敏感度证据、文件修订与图表更新。切勿纯粹为了增加回复篇幅而新增实验、图表或稿件段落。一项完整的方法学修正可能完全不需要比较图，特别是当现有的比较会混淆其他变更时。

<a id="common-failure-modes"></a>
## 常见错误模式

- 仅说 “clarified” 却未展示具体修改了什么。
- 报告数据却未解释其与审查意见疑虑的关联性。
- 在令人意外的指标已被定调为失败之后，才提出研究限制。
- 仅重述原始文本而非进行修改。
- 将受到质疑的主张移至补充材料却未正面回答。
- 微调参数以符合预期产出，却未宣告校准目标与独立证据。
- 在读者读到后续回复之前便向前参照该处。
- 在模型基准变更后，仍使用旧有的分析。
- 新增未能分离出受质疑因素的图表。
- 新增无法支持该主张的引用文献。
- 明明只有回复做了变更，却宣称稿件或补充材料已有修改。
- 拒绝某项要求却未解释原因或未提供有效的替代方案。

<a id="final-checks"></a>
## 最终检核

- [ ] 每则审查意见与子问题皆已记录。
- [ ] 每项回复皆直接回答当前的意见。
- [ ] 重大修改皆陈述了修改原因，以及是否已完整重跑分析。
- [ ] 主要回复的完整程度至少不下于审查意见，且无赘字充数或重复。
- [ ] 报告的每个数据皆具备经核实的出处来源与足够的诠释脉络。
- [ ] 每张图或表皆为最新版本、已在回复中引用，并于内文中详加解释。
- [ ] 结果皆有实质诠释，而非仅仅陈列数据。
- [ ] 回复指明了稿件中的修改之处，或解释了未作修改的原因。
- [ ] 相关意见回指先前回复，且未遗漏当前意见的独特疑虑。
- [ ] 残留的限制具体明确，且未夸大模型目前涵盖的范围。
- [ ] 术语、缩写、数学标记法、时态与回复排版格式维持一致。
- [ ] 最终行号皆指向指定的审阅版稿件算绘版本；未编行号的补充材料则使用经核实的项目定位点。
- [ ] 新起草的内文通过主张–证据、主张–处理范围、术语、禁用变体、重复字词、陈腔滥调、项目不建议词组以及格式化文件检核。
