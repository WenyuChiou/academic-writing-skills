<a id="argument-and-paragraph-function"></a>
## 论点与段落功能

梳理研究目的或缺口 → 研究问题或目标 → 方法 → 证据 → 结果 → 解读 → 限制 → 贡献。标记缺失、矛盾或孤立的环节。

段落的主题与目的应在开头几句中说明清楚，通常置于详细证据之前。按顺序阅读这些开头句；它们应构成连贯的小节大纲。每个段落应维持单一主要功能，除非简洁的过渡确实需要同时承担两项功能。

使开头、展开与结尾与该功能保持一致。结尾应完成由证据所确立的要点，或为具体的下一步做准备，而非仅仅重复开头。结尾不一定要是单独的总结句或过渡句。应将此视为读者理解度检验，而非固定句位或段落模板。

在起草前，先界定段落的功能、主张、证据、展开与衔接。在斟酌用词之前，先检查下列规划的逻辑，接着在完成的文章中验证相同的关系。

<a id="pre-draft-logic-check"></a>
### 起草前逻辑检查

进行章节或小节撰写时，应在起草个别段落之前安排好各段落的功能。进行局部实质改写时，应检视所提供的段落及其可用的相邻段落；切勿将受限的编辑扩大为整个章节的重组。若无法取得相邻内文，应陈述该限制，而非捏造其内容或保证连贯性。

- **段落之间：** 指出前一段落确立了什么、当前段落补充了什么，以及下一段落需要什么。检查该顺序是否提供了必要的背景与定义、推进了论点，并避免了重复的功能或未加说明的跳跃。指明确切的关系，例如对比、延伸、限定或结果；连接词无法弥补缺失的推理。
- **段落之内：** 指出其核心要点，以及规划中的各句如何展开、支持、解释或限定该要点。明确陈述比较与指称对象，在引用前提之前先予以介绍，并检查结尾是否顺理成章由证据得出。切勿将时间先后顺序或看似合理的序列视为因果关系的证明。

起草完成后，应通读整个段落及其与相邻段落的边界句子。使用主词与动作清晰明确的简洁直接句构；保留技术区别、必要条件与不确定性。简化语法绝不能产生断裂的语句碎片。请使用 [prose-and-citation-editing.md](prose-and-citation-editing.md) 进行详细的散文检核。

<a id="results-progression"></a>
### 结果推进

在结果（Results）部分，应在提及图表之前或同时陈述研究发现。报告支持该发现所需的证据，然后在相应的段落或小节边界处给出实质答案。切勿在每项结果之后附加空洞的综合讨论，或仅以统计数据、主题、路径或案例的再次条列来作结。

先提出主要模式或比较，再使用必要的数值或其他证据予以佐证。切勿仅依变数、群组或分图顺序报告数值，而让读者自行去发现研究结论。证据排序及其限定条件请参阅 [results-and-explanation.md](results-and-explanation.md)。

透过询问证据针对研究问题确立了什么（效应、对比、权衡取舍、边界或有支持的解释）来检验 “so what”。移除次要问题／研究问题（SQ/RQ）标签不应导致答案消失。切勿让描述性图表承载因果结论，亦切勿强求每张图表都要展现完整的反馈回路。

将可重现的步骤保留在方法（Methods）中。结果（Results）可包含由分析直接支持的发现与解释；广泛的、基于文献的或未经检验的机制解读与意涵，应保留给讨论（Discussion）。当文类明确将各章节整合时，可相应调整这些边界。

<a id="evidence-and-claim-scope"></a>
## 证据与主张处理范围

区分：

- 存在与不存在
- 方向与大小
- 不确定性与统计显著性
- 统计显著性与实务重要性
- 无法拒绝与等值证据
- 相关或预测与因果关系
- 模型适配度与机制有效性
- 组件层级相似性与整体重现
- 模拟行为与真实世界行为

在影响意涵之处，必须提供分母、比较集合、母体、时间、地点与条件。唯有在明确的标准与分析提供支持时，方可使用验证、等值、非劣性或一致性等用语。

缺乏支持的解释应作为可能的解读置于讨论（Discussion）中，或予以删除。绝不可仅因审稿人要求 “why.” 就增添机制。

对于基于模型的解释，应区分四个层次：已核验的模型规则、观察到的产出、经分析检验或直接支持的解释，以及看似合理但未经检验的机制。规则描述的是模型允许什么；规则本身并不能证明为何会出现总体趋势。应对未经检验的解释加以限定，并指明所需的诊断分析，切勿将模型逻辑转化为因果证据。同样地，引入真实世界政策作为背景，并不能证明模型已实作或落实该政策。

在研究限制（Limitations）章节中，应先指明具体的资料、设计、测量、模型或验证限制条件。接着在需要时，说明该限制条件如何限制推论或结果的运用。切勿将该章节构建在「谨慎解读结果」这类泛泛的警告之上，亦切勿将研究发现本身视为方法学上的限制。

切勿仅为了保留偏好的结论而淡化或隐瞒研究限制。未来工作可以沿着推论界线展开，但绝不能取代对推论界线的陈述。

<a id="abstract-and-conclusion"></a>
## 摘要与结论

依据目前的证据图谱建构摘要：

1. 重要性或问题
2. 未解决的缺口
3. 目标或问题
4. 最低可解读设计
5. 依问题或分析顺序呈现可明确区分的研究发现
6. 贡献、意涵或使用边界

为每个主要研究问题提供实质的答案。保留足够具名的关系、组别对比、方向与限定条件，使答案在没有内部代码或图表的情况下仍清晰可懂。将字数限制视为上限，而非抹煞关键意涵的借口。

明确指认方法及其作用、研究对象是谁或何物，以及解读答案所必需的时间、地点、资料集或分析处理范围。仅在字数限制来自当前投稿期刊／会议或作者契约时才予以套用。使用 [conclusion-and-abstract.md](conclusion-and-abstract.md) 进行灵活的信息功能划分、直接的结论开头以及精简检查；切勿将该顺序硬套为固定句数，或转化为缺乏支持的试验平台／最佳化主张。

围绕以下重点建构结论：

1. 本研究做了什么
2. 依分析顺序呈现的综合答案
3. 意涵、贡献与使用边界

切勿添加新证据或照抄摘要。保留研究实际的任务动词与推论层级。

<a id="terminology-repetition-and-flow"></a>
## 术语、重复与行文流畅度

请使用产生或包含证据的实体名称。切勿混用受试者、回应、资料集、模型、模拟或估计值。

每个概念使用一个稳定的术语。仅在术语登录表有指明时，才允许出现情境变体。不明确的代称应在局部就地厘清。

对于重要指标，应在项目纪录或现有的方法／附注中保留其定义、分子、分母、单位、比较以及汇整／解读边界。相同的百分比符号并不代表标准化方式不同的指标彼此等值。应区分百分比之间的差异（百分点）与相对百分比变动。在缺乏该证据的情况下，切勿将分别排序的曲线差异称为事件配对赔付。

在相关的阅读边界处定义缩写，并遵循期刊／会议与作者惯例。独立阅读的摘要或补充材料（SM）可能需要各自的首次定义；图表说明文字可能需要自成一体的解释。切勿在每个图表说明中机械式地重新定义每个缩写，亦勿假定正文中的定义足以让所有附随产物清晰易懂。当读者同时需要机构脉络或指标目的时，仅有定义是不够的。

切勿纯粹为了多样性而轮替技术术语。应区分以下四种情况：

1. 已定义构念、模型、母体或结果的必要重复
2. 为维持章节主体或比较的有益重复
3. 非技术词汇、短语、句首开头或段落功能的可避免重复
4. 未增加新证据或推理的完全或近似重复文字

对于感觉公式化或类似 AI 风格的文字，仅报告可观察到的特征：泛泛的后设话语、空洞的强调词、陈腔滥调的过渡词、模糊的主词、重复的节奏、过多的预告与总结句、对称但内容贫乏的清单，或缺乏支持的综合归纳。绝不可从这些特征推断或指称其为 AI 所写。仅在修改能够提升精确度、证据连结或信息流畅度时，才替换被标记的模式。

在三个层次检验流畅度：

- **句子：** 在有助于理解时，将已知信息置于新信息之前；使语法主词与所讨论的实体保持一致
- **段落：** 从主张出发，经由证据与解释展开单一主要功能；结尾时解决该论点，或确立与后续内容的具体关系
- **章节：** 依序阅读主题句与结尾句；验证论述的层层推进，而非反复重述

使用能够指明确切关系的过渡词——对比、因果、条件、延伸、限定或结果。切勿仅为了让相邻段落听起来有连贯感而插入过渡词。

<a id="numbers-citations-and-visuals"></a>
## 数值、引用与图表

将重要数值与元数据追溯至来源。检查单位、分母、四舍五入、样本子集、方程式、图形标签、表格附注与补充文件项目。

外部事实、既有发现、既定定义、资料来源、参数、门槛值与方法学理据皆须有支持依据。核对正文引用与参考文献清单，以及其所支持的主张。

解释每个图表的主要模式、相关证据、不确定性以及与研究问题的关系。唯有在有依据支持时方可解释机制。检视说明文字、分图面板、图例、座标轴、单位、标注、解析度、易读性以及跨文件编号。

以图表在最终文件中的实际尺寸进行检视，而非仅检视放大后的原始文件。使用 [figures-tables-and-supplements.md](figures-tables-and-supplements.md) 检查标签易读性、留白平衡、说明文字／注释功能以及跨产物查核。项目选择（例如粗体引用或纯文字范围连接符号）仍属偏好，并非通用的投稿标准。

<a id="exact-candidate-gate"></a>
## 确切候选版本查核关卡

审查最终改写后将交付的确切文字，而非来源段落或早期的候选版本。局部的编辑仍必须通过以下具体范围的检查：

1. 段落功能、主张、证据、展开与衔接；
2. 保留锁定意涵与站得住脚的主张处理范围；
3. 稳定的术语与缩写；
4. 完全与语意重复、陈腔滥调的过渡词、模糊的综合归纳、过多的总结以及项目不建议使用的短语；
5. 每一项保留或新增的引用皆有依据，并核对每一项删除的引用；以及
6. 在前后段落可用时，与前后段落的流畅衔接。

若项目具备文风或术语规范档，即使在轻量模式下亦应套用。将确定性的发现视为情境判断的提示，但切勿默不作声地忽视。若通过此关卡后有更动任何文字，必须针对新的确切候选版本重新执行受影响的检查。

这些检查取决于所要求的操作：实质段落检视会检验保留的支持依据；仅限文法的校正则维持原样未变且已核实的支持依据，不声明进行了新的引用审查。将整个章节的功能应用于章节工作，而非套用到每个孤立的句子。请指明任何无法取得的脉络或来源。

<a id="four-pass-review"></a>
## 四轮检视

整篇论文／投稿文件的检视请使用完整的审视轮次。在大幅修改的小节或章节及其受影响的相依项目中套用这些轮次；表面文字修订请使用受限候选版本关卡。既有的项目状态仅为脉络，并非要求进行全面检视的证据。

<a id="pass-1-argument-and-structure"></a>
### 第 1 轮：论点与结构

检验读者功能、研究缺口、研究目的、问题、组织架构、段落开头与研究贡献。

<a id="pass-2-evidence-and-consistency"></a>
### 第 2 轮：证据与一致性

对照产出、样本、单位、方程式、图表、表格、引用、主张处理范围与传播影响来检验方法。

<a id="pass-3-scholarly-prose"></a>
### 第 3 轮：学术散文

首先稳定术语与缩写。接着检视完全重复、重复短语与句首、过度使用非技术词汇、陈腔滥调、过长的连续名词堆叠、模糊的强调词、主词不稳定、语法、时态、语态、符号标记以及段落之间的流畅度。保留必要的技术性重复，切勿将同义词轮替作为表面修饰手段。修改后，在编辑后的确切候选版本上再次执行此轮检视；编辑前文字的检核结果不能作为修改后版本的保证。

<a id="pass-4-delivery-integrity"></a>
### 第 4 轮：交付完整性

重读确切的交付成果。查核摘要、参考文献、编号、必要声明、追踪修订、注解、文件名称、算图呈现、随附文件与发布状态。

当第 4 轮揭露实质问题时，修正后应重新执行受影响的先前轮次。
