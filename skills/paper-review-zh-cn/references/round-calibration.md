<a id="review-round-calibration"></a>
# 审稿轮次校准

<a id="determine-the-stage"></a>
## 判定阶段

当使用者提供明确的 R1–R4 标签时请使用之。否则请使用基础工作流程的成熟度标签。意见数量、文件命名、表面的行文品质以及修订追踪的存在，皆不能用来确立轮次。

<a id="r1-or-developmental"></a>
## R1 或发展阶段

优先处理研究定位、贡献、稿件架构、缺失的读者功能、方法可行性，以及从问题或目标到规划证据的对应。仅在稿件有需要时才提供结构指引；切勿将单一范本强加于所有文体。

<a id="r2-or-substantive"></a>
## R2 或实质阶段

当可取得先前的意见时，先从遵循度稽核开始。接着着重方程式与符号一致性、图文对齐、方法完整性、术语、有证据支持的诠释，以及讨论（Discussion）结构。

在将当前产件与先前的指示进行比较之前，切勿主张 R1 问题尚未解决。

<a id="r3-or-integration"></a>
## R3 或整合阶段

优先处理未解决的阻碍、修订引起的退化、最终诠释、摘要连动传播、术语、符号表示、图表说明文字以及结论（Conclusion）。当草稿稳定时保持审稿聚焦，但应提报任何新发现的高风险问题。

切勿从意见的大幅减少推论已接近准备就绪。切勿仅因历史范例延后处理某个具科学实质意义的章节，就将其延后处理。

<a id="r4-or-submission"></a>
## R4 或投稿阶段

优先处理确切交付成果、证据与处理范围完整性、摘要（Abstract）与结论（Conclusion）的同步、参考文献、图表、补充材料排序、作者与资助元数据、声明事项、期刊要求、修订追踪、意见以及排版呈现。

当仍存在高严重度阻碍、缺失来源、过时的附随文件或未核实的元数据时，切勿使用 `FINAL` 或 `SUBMISSION_READY`。

<a id="cross-round-ledger"></a>
## 跨轮次纪录帐

将先前的问题分类为：

- `RESOLVED`：所要求的变更已存在，且未引入新的冲突
- `PARTIAL`：部分请求已获处理，但仍有实质要素残存
- `OPEN`：当前证据确认其依然存在
- `REGRESSED`：原本已获解决，但后续的编辑再次将其引入
- `WAIVED`：经授权的决定保留该问题，并附有理由与风险说明
- `NOT_VERIFIABLE`：所需之先前产件或来源无法取得

进行实质修订后，应重新检视上游的研究定位与下游的摘要，而非仅检查被提出意见的句子。

<a id="audit-comment-threads-against-the-current-artifact"></a>
## 依当前产件稽核意见讨论串

当提供先前的意见、作者回复、修订追踪或已解决的意见讨论串时，请将三个证据层次分开：

1. 审稿人指示或要求的决定
2. 作者的回复或主张采取的行动
3. 在当前稿件及受影响附随产件中已核实的变更

诸如 “revised,” “fixed,” 或 “addressed” 的回复并不能确立问题已获解决。请在现行产件中找出所主张的变更，查核其是否符合指示，并确认其未造成矛盾，亦未留下过时的摘要（Abstract）、结论（Conclusion）、图、表、方程式、图表说明、补充材料或回复信。

当存在回复但已核实的变更仅处理了部分请求时，将该问题归类为 `PARTIAL`。当前证据显示所要求的变更不存在或实质不足时，使用 `OPEN`。当比对所需的先前指示、引用来源、较早版本、修订追踪基准或现行产件无法取得时，使用 `NOT_VERIFIABLE`。切勿仅凭回复文字或 UI 解决状态，就将讨论串提升为 `RESOLVED`。
