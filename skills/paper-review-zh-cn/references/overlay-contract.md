<a id="progressive-review-overlay-contract"></a>
# 渐进式审查叠加层契约

<a id="precedence"></a>
## 优先顺序

按顺序套用：

1. 安全、伦理与研究诚信
2. 已核实的稿件证据与权威项目事实
3. 明确的当前使用者指示
4. 适用的发表处与报告要求
5. `academic-writing-skills-zh-cn` 通用核心与研究设计配接器
6. 适用的方法与领域模块
7. 明确的审稿人偏好与已确认的项目先例

浮现冲突而非默不作声地自行选择。领域常规或审稿人偏好绝不能凌驾于证据、伦理或经已核实的发表处规定之上。

<a id="module-selection"></a>
## 模块选取

在询问使用者之前，先运用稿件证据。从研究问题、实体、测量指标、模型、估计目标、方程式、图形以及主张的推论（而非单一关键字）中推断候选模块。

选取最小且充分的模块集。记录载入各模块的原因。仅在歧义会实质改变所需证据、主张处理范围或审查样态时，方可提出具针对性的问题。

切勿让某个模块在未明确说明的情况下启动另一个模块。在跨领域混合研究中，每个模块仅能套用于其处理范围内的主张与产物。

<a id="evidence-safety"></a>
## 证据安全性

每项主张皆须有适当的证据。区分直接结果、经检验的机制、文献支持的解读、看似合理的替代解释与推测。

切勿将共同显著视为等值、将各自的显著性结果视为显著差异、将系数相似性视为形式上的一致、将良好的适配度视为机制有效性、将程式码执行视为核验、将模拟视为观测，或将产出一致性视为行为有效性。

<a id="rule-classification"></a>
## 规则分类

将叠加层内容分类为：

- 方法或设计要求
- 领域技术检查
- 发表处或报告要求
- 审稿人偏好
- 项目先例

绝不可将审稿人、期刊、实验室或项目规则提升为通用要求。项目事实必须保留在项目状态中，而非可重复使用的领域参考资料。

<a id="output-control"></a>
## 产出控制

仅在有先前证据时使用前一轮状态。针对实际的章节与产物发表意见。由重大程度决定审查篇幅。切勿纯粹为了产生更长的备忘录而重复基础审查内容。
