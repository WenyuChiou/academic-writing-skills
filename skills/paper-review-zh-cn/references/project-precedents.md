<a id="conditional-project-precedents"></a>
# 条件式项目先例

仅在使用者或稿件确立了确切项目后，方可载入此文件。将每一项目视为需要对照当前项目状态予以确认的先前审查脉络。

<a id="wenyu-type-flood-adaptation-projects"></a>
## Wenyu 类型洪水调适项目

- 区分社会脆弱度群体标签与住宅产权类别；仅在分析将两者连结时，才要求提供明确的对应关系。
- 检查研究结果是否展现了超出输入数值或模型结构之直接结果的意涵。
- 对照当前的方法（Methods）与分析产出，查核敏感度符号。

切勿从另一篇 Wenyu 稿件中汇入样本数、经费来源、模型版本、研究问题、作者角色或偏好术语。

<a id="madan-type-water-policy-abm-projects"></a>
## Madan 类型水资源政策 ABM 项目

- 在强制使用标签之前，先从项目来源中核实当前的情境名称与目标。
- 检查相较于当前基准线，学习机制增加了什么，以及社会传播与经济遵循是否分别表征。
- 将先前关于政治可行性的意见视为需要当前管辖权证据的询问。

<a id="ylin-type-framework-projects"></a>
## YLin 类型架构项目

- 检查是否明确区分双向反馈、即时交换、模块化与重复使用。
- 核实当前的竞争对手文献，而非硬性要求固定方法清单。

<a id="husamettin-type-hydrodynamic-projects"></a>
## Husamettin 类型水动力学项目

- 重新检查研究情境与模型设定各自的功能、耦合定义、模型数量、事件纳入、图形与易读性。
- 在质疑图表说明文字之前，先确认当前的模型能力。

<a id="shrouq-type-sensor-or-surrogate-projects"></a>
## Shrouq 类型感测器或代理模型项目

- 在评断迁移学习术语之前，先核实来源与目标设定。
- 对照当前证据，检查感测器配置、时间解析度、划分设计与研究缺口主张。

<a id="historical-review-patterns"></a>
## 历史审查模式

过去的直接意见、图表重新设计、用词选择以及意见数量轨迹，可用于校准语气或揭示反复出现的失败模式。除非保留在问题或决定总帐中，否则它们并非当前的指示。
