<a id="conditional-project-precedents"></a>
# 條件式專案先例

僅在使用者或稿件確立了確切專案後，方可載入此檔案。將每一項目視為需要對照當前專案狀態予以確認的先前審查脈絡。

<a id="wenyu-type-flood-adaptation-projects"></a>
## Wenyu 類型洪水調適專案

- 區分社會脆弱度群體標籤與住宅產權類別；僅在分析將兩者連結時，才要求提供明確的對應關係。
- 檢查研究結果是否展現了超出輸入數值或模型結構之直接結果的意涵。
- 對照當前的方法（Methods）與分析產出，查核敏感度符號。

切勿從另一篇 Wenyu 稿件中匯入樣本數、經費來源、模型版本、研究問題、作者角色或偏好術語。

<a id="madan-type-water-policy-abm-projects"></a>
## Madan 類型水資源政策 ABM 專案

- 在強制使用標籤之前，先從專案來源中核實當前的情境名稱與目標。
- 檢查相較於當前基準線，學習機制增加了什麼，以及社會傳播與經濟遵循是否分別表徵。
- 將先前關於政治可行性的意見視為需要當前管轄權證據的詢問。

<a id="ylin-type-framework-projects"></a>
## YLin 類型架構專案

- 檢查是否明確區分雙向反饋、即時交換、模組化與重複使用。
- 核實當前的競爭對手文獻，而非硬性要求固定方法清單。

<a id="husamettin-type-hydrodynamic-projects"></a>
## Husamettin 類型水動力學專案

- 重新檢查研究情境與模型設定各自的功能、耦合定義、模型數量、事件納入、圖形與易讀性。
- 在質疑圖表說明文字之前，先確認當前的模型能力。

<a id="shrouq-type-sensor-or-surrogate-projects"></a>
## Shrouq 類型感測器或代理模型專案

- 在評斷遷移學習術語之前，先核實來源與目標設定。
- 對照當前證據，檢查感測器配置、時間解析度、劃分設計與研究缺口主張。

<a id="historical-review-patterns"></a>
## 歷史審查模式

過去的直接意見、圖表重新設計、用詞選擇以及意見數量軌跡，可用於校準語氣或揭示反覆出現的失敗模式。除非保留在問題或決定總帳中，否則它們並非當前的指示。
