# 圖表展示、符號標記與來源出處審查

<a id="load-this-module-selectively"></a>
## 選擇性載入此模組

當稿件在圖形或表格中使用了方程式、形式符號、帶索引的變數、正規化或彙整序列、綜合指標、陰影範圍、發散度量、情境摘要或其他衍生數量時，應載入此模組。

切勿僅因稿件包含簡單的描述性表格，或是變數、單位與來源已十分明確且未經轉換的繪圖，就載入此模組。單憑圖表檔案名稱、單一符號或泛泛提及不確定性，本身並不足以構成載入依據。

<a id="build-an-equation-and-notation-ledger"></a>
## 建立方程式與符號標記總帳

針對每個重要符號，記錄其定義、單位或尺度、定義域、索引、首次定義位置，以及出現該符號的每個產物。接著查核：

- 同一符號未默默代表不同的變數
- 同一變數未在無明確理由的情況下被賦予相互衝突的符號
- 空間、時間、群組、情境、模型與代理人索引保持明確區隔
- 向量、矩陣、參數、估計值、隨機變數與觀測值使用一致的符號標記
- 方程式、散文、圖形、表格、說明文字、附錄與補充資料彼此相符
- 敏感度分析與實作符號標記與方法（Methods）中的定義一致
- 轉換後、正規化或無因次量仍可與其來源變數明確區分

切勿為未定義的符號捏造定義。應將其分類為缺失、模糊、衝突或無法核實，並指明解決該問題所需的權限。

<a id="trace-derived-display-quantities"></a>
## 追溯衍生顯示量

針對每個非直接報告變數的重要數量，進行以下追溯：

```text
source data or model output -> transformation or equation -> aggregation or normalization -> displayed value -> textual claim
```

在方法（Methods）、方程式、可重現的程式碼規則、表格附註或說明文字定義中，必須具備可追溯的依據。檢查：

- 分子、分母、基準線、參照群組與正規化範圍
- 跨時間、空間、人員、執行、模型或情境的彙整層級與加權方式
- 不確定性定義，包括帶狀區域顯示的是離散度、信賴區間、可信區間、分位數、系集還是敏感度範圍
- 缺失值、設限值、零分母以及排除之執行或群組的處理方式
- 省略的模型、事件、群組、情境或分圖是否具備陳述明確且站得住腳的理由
- 說明文字是否定義了非顯而易見的轉換與不確定性，而非僅指出顏色與分圖
- 正文是否以相同的尺度與相同的比較基準解讀所展示的數量

切勿從視覺外觀推斷來源出處。若無法取得轉換或排除規則，應將該主張標記為無法核實，並將任何要求的修改限定於澄清說明，而非重構分析。

<a id="report-material-failures"></a>
## 報告重大缺失

區分：

- **符號衝突（notation conflict）：** 相同的符號或標籤具有不相容的涵義
- **定義缺口（definition gap）：** 符號、轉換或不確定性展示缺乏定義
- **來源缺口（provenance gap）：** 展示的數值無法追溯至經授權的來源或規則
- **圖表與主張不符（display–claim mismatch）：** 正文斷言了展示內容不支援的比較、尺度或不確定性涵義
- **跨產物回歸（cross-artifact regression）：** 後續編輯更新了某個產物，但導致方程式、說明文字、補充資料或摘要過時

套用基礎嚴重度與證據狀態系統。除非歧義性、可重現性或主張的解讀受到實質影響，否則切勿將形式美化類的符號標記偏好列為阻礙項目。
