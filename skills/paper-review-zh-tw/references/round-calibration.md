# 審稿輪次校準

<a id="determine-the-stage"></a>
## 判定階段

當使用者提供明確的 R1–R4 標籤時請使用之。否則請使用基礎工作流程的成熟度標籤。意見數量、檔案命名、表面的行文品質以及修訂追蹤的存在，皆不能用來確立輪次。

<a id="r1-or-developmental"></a>
## R1 或發展階段

優先處理研究定位、貢獻、稿件架構、缺失的讀者功能、方法可行性，以及從問題或目標到規劃證據的對應。僅在稿件有需要時才提供結構指引；切勿將單一範本強加於所有文體。

<a id="r2-or-substantive"></a>
## R2 或實質階段

當可取得先前的意見時，先從遵循度稽核開始。接著著重方程式與符號一致性、圖文對齊、方法完整性、術語、有證據支持的詮釋，以及討論（Discussion）結構。

在將當前產件與先前的指示進行比較之前，切勿主張 R1 問題尚未解決。

<a id="r3-or-integration"></a>
## R3 或整合階段

優先處理未解決的阻礙、修訂引起的退化、最終詮釋、摘要連動傳播、術語、符號表示、圖表說明文字以及結論（Conclusion）。當草稿穩定時保持審稿聚焦，但應提報任何新發現的高風險問題。

切勿從意見的大幅減少推論已接近準備就緒。切勿僅因歷史範例延後處理某個具科學實質意義的章節，就將其延後處理。

<a id="r4-or-submission"></a>
## R4 或投稿階段

優先處理確切交付成果、證據與處理範圍完整性、摘要（Abstract）與結論（Conclusion）的同步、參考文獻、圖表、補充資料排序、作者與資助中繼資料、聲明事項、期刊要求、修訂追蹤、意見以及排版呈現。

當仍存在高嚴重度阻礙、缺失來源、過時的附隨檔案或未核實的中繼資料時，切勿使用 `FINAL` 或 `SUBMISSION_READY`。

<a id="cross-round-ledger"></a>
## 跨輪次紀錄帳

將先前的問題分類為：

- `RESOLVED`：所要求的變更已存在，且未引入新的衝突
- `PARTIAL`：部分請求已獲處理，但仍有實質要素殘存
- `OPEN`：當前證據確認其依然存在
- `REGRESSED`：原本已獲解決，但後續的編輯再次將其引入
- `WAIVED`：經授權的決定保留該問題，並附有理由與風險說明
- `NOT_VERIFIABLE`：所需之先前產件或來源無法取得

進行實質修訂後，應重新檢視上游的研究定位與下游的摘要，而非僅檢查被提出意見的句子。

<a id="audit-comment-threads-against-the-current-artifact"></a>
## 依當前產件稽核意見討論串

當提供先前的意見、作者回覆、修訂追蹤或已解決的意見討論串時，請將三個證據層次分開：

1. 審稿人指示或要求的決定
2. 作者的回覆或主張採取的行動
3. 在當前稿件及受影響附隨產件中已核實的變更

諸如 “revised,” “fixed,” 或 “addressed” 的回覆並不能確立問題已獲解決。請在現行產件中找出所主張的變更，查核其是否符合指示，並確認其未造成矛盾，亦未留下過時的摘要（Abstract）、結論（Conclusion）、圖、表、方程式、圖表說明、補充資料或回覆信。

當存在回覆但已核實的變更僅處理了部分請求時，將該問題歸類為 `PARTIAL`。當前證據顯示所要求的變更不存在或實質不足時，使用 `OPEN`。當比對所需的先前指示、引用來源、較早版本、修訂追蹤基準或現行產件無法取得時，使用 `NOT_VERIFIABLE`。切勿僅憑回覆文字或 UI 解決狀態，就將討論串提升為 `RESOLVED`。
