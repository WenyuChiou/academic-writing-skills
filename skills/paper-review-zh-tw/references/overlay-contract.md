# 漸進式審查疊加層契約

<a id="precedence"></a>
## 優先順序

按順序套用：

1. 安全、倫理與研究誠信
2. 已核實的稿件證據與權威專案事實
3. 明確的當前使用者指示
4. 適用的發表處與報告要求
5. `academic-writing-skills-zh-tw` 通用核心與研究設計配接器
6. 適用的方法與領域模組
7. 明確的審稿人偏好與已確認的專案先例

浮現衝突而非默不作聲地自行選擇。領域常規或審稿人偏好絕不能凌駕於證據、倫理或經已核實的發表處規定之上。

<a id="module-selection"></a>
## 模組選取

在詢問使用者之前，先運用稿件證據。從研究問題、實體、測量指標、模型、估計目標、方程式、圖形以及主張的推論（而非單一關鍵字）中推斷候選模組。

選取最小且充分的模組集。記錄載入各模組的原因。僅在歧義會實質改變所需證據、主張處理範圍或審查樣態時，方可提出具針對性的問題。

切勿讓某個模組在未明確說明的情況下啟動另一個模組。在跨領域混合研究中，每個模組僅能套用於其處理範圍內的主張與產物。

<a id="evidence-safety"></a>
## 證據安全性

每項主張皆須有適當的證據。區分直接結果、經檢驗的機制、文獻支持的解讀、看似合理的替代解釋與推測。

切勿將共同顯著視為等值、將各自的顯著性結果視為顯著差異、將係數相似性視為形式上的一致、將良好的適配度視為機制有效性、將程式碼執行視為核驗、將模擬視為觀測，或將產出一致性視為行為有效性。

<a id="rule-classification"></a>
## 規則分類

將疊加層內容分類為：

- 方法或設計要求
- 領域技術檢查
- 發表處或報告要求
- 審稿人偏好
- 專案先例

絕不可將審稿人、期刊、實驗室或專案規則提升為通用要求。專案事實必須保留在專案狀態中，而非可重複使用的領域參考資料。

<a id="output-control"></a>
## 產出控制

僅在有先前證據時使用前一輪狀態。針對實際的章節與產物發表意見。由重大程度決定審查篇幅。切勿純粹為了產生更長的備忘錄而重複基礎審查內容。
