<a id="argument-and-paragraph-function"></a>
## 論點與段落功能

梳理研究目的或缺口 → 研究問題或目標 → 方法 → 證據 → 結果 → 解讀 → 限制 → 貢獻。標記缺失、矛盾或孤立的環節。

段落的主題與目的應在開頭幾句中說明清楚，通常置於詳細證據之前。按順序閱讀這些開頭句；它們應構成連貫的小節大綱。每個段落應維持單一主要功能，除非簡潔的過渡確實需要同時承擔兩項功能。

使開頭、展開與結尾與該功能保持一致。結尾應完成由證據所確立的要點，或為具體的下一步做準備，而非僅僅重複開頭。結尾不一定要是單獨的總結句或過渡句。應將此視為讀者理解度檢驗，而非固定句位或段落模板。

在起草前，先界定段落的功能、主張、證據、展開與銜接。在斟酌用詞之前，先檢查下列規劃的邏輯，接著在完成的文章中驗證相同的關係。

<a id="pre-draft-logic-check"></a>
### 起草前邏輯檢查

進行章節或小節撰寫時，應在起草個別段落之前安排好各段落的功能。進行局部實質改寫時，應檢視所提供的段落及其可用的相鄰段落；切勿將受限的編輯擴大為整個章節的重組。若無法取得相鄰內文，應陳述該限制，而非捏造其內容或保證連貫性。

- **段落之間：** 指出前一段落確立了什麼、當前段落補充了什麼，以及下一段落需要什麼。檢查該順序是否提供了必要的背景與定義、推進了論點，並避免了重複的功能或未加說明的跳躍。指明確切的關係，例如對比、延伸、限定或結果；連接詞無法彌補缺失的推理。
- **段落之內：** 指出其核心要點，以及規劃中的各句如何展開、支持、解釋或限定該要點。明確陳述比較與指稱對象，在引用前提之前先予以介紹，並檢查結尾是否順理成章由證據得出。切勿將時間先後順序或看似合理的序列視為因果關係的證明。

起草完成後，應通讀整個段落及其與相鄰段落的邊界句子。使用主詞與動作清晰明確的簡潔直接句構；保留技術區別、必要條件與不確定性。簡化語法絕不能產生斷裂的語句碎片。請使用 [prose-and-citation-editing.md](prose-and-citation-editing.md) 進行詳細的散文檢核。

<a id="results-progression"></a>
### 結果推進

在結果（Results）部分，應在提及圖表之前或同時陳述研究發現。報告支持該發現所需的證據，然後在相應的段落或小節邊界處給出實質答案。切勿在每項結果之後附加空洞的綜合討論，或僅以統計數據、主題、路徑或案例的再次條列來作結。

先提出主要模式或比較，再使用必要的數值或其他證據予以佐證。切勿僅依變數、群組或分圖順序報告數值，而讓讀者自行去發現研究結論。證據排序及其限定條件請參閱 [results-and-explanation.md](results-and-explanation.md)。

透過詢問證據針對研究問題確立了什麼（效應、對比、權衡取捨、邊界或有支持的解釋）來檢驗 “so what”。移除次要問題／研究問題（SQ/RQ）標籤不應導致答案消失。切勿讓描述性圖表承載因果結論，亦切勿強求每張圖表都要展現完整的反饋迴路。

將可重現的步驟保留在方法（Methods）中。結果（Results）可包含由分析直接支持的發現與解釋；廣泛的、基於文獻的或未經檢驗的機制解讀與意涵，應保留給討論（Discussion）。當文類明確將各章節整合時，可相應調整這些邊界。

<a id="evidence-and-claim-scope"></a>
## 證據與主張處理範圍

區分：

- 存在與不存在
- 方向與大小
- 不確定性與統計顯著性
- 統計顯著性與實務重要性
- 無法拒絕與等值證據
- 相關或預測與因果關係
- 模型適配度與機制有效性
- 組件層級相似性與整體重現
- 模擬行為與真實世界行為

在影響意涵之處，必須提供分母、比較集合、母體、時間、地點與條件。唯有在明確的標準與分析提供支持時，方可使用驗證、等值、非劣性或一致性等用語。

缺乏支持的解釋應作為可能的解讀置於討論（Discussion）中，或予以刪除。絕不可僅因審稿人要求 “why.” 就增添機制。

對於基於模型的解釋，應區分四個層次：已核驗的模型規則、觀察到的產出、經分析檢驗或直接支持的解釋，以及看似合理但未經檢驗的機制。規則描述的是模型允許什麼；規則本身並不能證明為何會出現總體趨勢。應對未經檢驗的解釋加以限定，並指明所需的診斷分析，切勿將模型邏輯轉化為因果證據。同樣地，引入真實世界政策作為背景，並不能證明模型已實作或落實該政策。

在研究限制（Limitations）章節中，應先指明具體的資料、設計、測量、模型或驗證限制條件。接著在需要時，說明該限制條件如何限制推論或結果的運用。切勿將該章節構建在「謹慎解讀結果」這類泛泛的警告之上，亦切勿將研究發現本身視為方法學上的限制。

切勿僅為了保留偏好的結論而淡化或隱瞞研究限制。未來工作可以沿著推論界線展開，但絕不能取代對推論界線的陳述。

<a id="abstract-and-conclusion"></a>
## 摘要與結論

依據目前的證據圖譜建構摘要：

1. 重要性或問題
2. 未解決的缺口
3. 目標或問題
4. 最低可解讀設計
5. 依問題或分析順序呈現可明確區分的研究發現
6. 貢獻、意涵或使用邊界

為每個主要研究問題提供實質的答案。保留足夠具名的關係、組別對比、方向與限定條件，使答案在沒有內部代碼或圖表的情況下仍清晰可懂。將字數限制視為上限，而非抹煞關鍵意涵的藉口。

明確指認方法及其作用、研究對象是誰或何物，以及解讀答案所必需的時間、地點、資料集或分析處理範圍。僅在字數限制來自當前投稿期刊／會議或作者契約時才予以套用。使用 [conclusion-and-abstract.md](conclusion-and-abstract.md) 進行靈活的資訊功能劃分、直接的結論開頭以及精簡檢查；切勿將該順序硬套為固定句數，或轉化為缺乏支持的試驗平台／最佳化主張。

圍繞以下重點建構結論：

1. 本研究做了什麼
2. 依分析順序呈現的綜合答案
3. 意涵、貢獻與使用邊界

切勿添加新證據或照抄摘要。保留研究實際的任務動詞與推論層級。

<a id="terminology-repetition-and-flow"></a>
## 術語、重複與行文流暢度

請使用產生或包含證據的實體名稱。切勿混用受試者、回應、資料集、模型、模擬或估計值。

每個概念使用一個穩定的術語。僅在術語登錄表有指明時，才允許出現情境變體。不明確的代稱應在局部就地釐清。

對於重要指標，應在專案紀錄或現有的方法／附註中保留其定義、分子、分母、單位、比較以及彙整／解讀邊界。相同的百分比符號並不代表正規化方式不同的指標彼此等值。應區分百分比之間的差異（百分點）與相對百分比變動。在缺乏該證據的情況下，切勿將分別排序的曲線差異稱為事件配對賠付。

在相關的閱讀邊界處定義縮寫，並遵循期刊／會議與作者慣例。獨立閱讀的摘要或補充材料（SM）可能需要各自的首次定義；圖表說明文字可能需要自成一體的解釋。切勿在每個圖表說明中機械式地重新定義每個縮寫，亦勿假定正文中的定義足以讓所有附隨產物清晰易懂。當讀者同時需要機構脈絡或指標目的時，僅有定義是不夠的。

切勿純粹為了多樣性而輪替技術術語。應區分以下四種情況：

1. 已定義構念、模型、母體或結果的必要重複
2. 為維持章節主體或比較的有益重複
3. 非技術詞彙、短語、句首開頭或段落功能的可避免重複
4. 未增加新證據或推理的完全或近似重複文字

對於感覺公式化或類似 AI 風格的文字，僅報告可觀察到的特徵：泛泛的後設話語、空洞的強調詞、陳腔濫調的過渡詞、模糊的主詞、重複的節奏、過多的預告與總結句、對稱但內容貧乏的清單，或缺乏支持的綜合歸納。絕不可從這些特徵推斷或指稱其為 AI 所寫。僅在修改能夠提升精確度、證據連結或資訊流暢度時，才替換被標記的模式。

在三個層次檢驗流暢度：

- **句子：** 在有助於理解時，將已知資訊置於新資訊之前；使語法主詞與所討論的實體保持一致
- **段落：** 從主張出發，經由證據與解釋展開單一主要功能；結尾時解決該論點，或確立與後續內容的具體關係
- **章節：** 依序閱讀主題句與結尾句；驗證論述的層層推進，而非反覆重述

使用能夠指明確切關係的過渡詞——對比、因果、條件、延伸、限定或結果。切勿僅為了讓相鄰段落聽起來有連貫感而插入過渡詞。

<a id="numbers-citations-and-visuals"></a>
## 數值、引用與圖表

將重要數值與中繼資料追溯至來源。檢查單位、分母、四捨五入、樣本子集、方程式、圖形標籤、表格附註與補充文件項目。

外部事實、既有發現、既定定義、資料來源、參數、門檻值與方法學理據皆須有支持依據。核對正文引用與參考文獻清單，以及其所支持的主張。

解釋每個圖表的主要模式、相關證據、不確定性以及與研究問題的關係。唯有在有依據支持時方可解釋機制。檢視說明文字、分圖面板、圖例、座標軸、單位、標註、解析度、易讀性以及跨檔案編號。

以圖表在最終文件中的實際尺寸進行檢視，而非僅檢視放大後的原始檔案。使用 [figures-tables-and-supplements.md](figures-tables-and-supplements.md) 檢查標籤易讀性、留白平衡、說明文字／註釋功能以及跨產物查核。專案選擇（例如粗體引用或純文字範圍連接符號）仍屬偏好，並非通用的投稿標準。

<a id="exact-candidate-gate"></a>
## 確切候選版本查核關卡

審查最終改寫後將交付的確切文字，而非來源段落或早期的候選版本。局部的編輯仍必須通過以下具體範圍的檢查：

1. 段落功能、主張、證據、展開與銜接；
2. 保留鎖定意涵與站得住腳的主張處理範圍；
3. 穩定的術語與縮寫；
4. 完全與語意重複、陳腔濫調的過渡詞、模糊的綜合歸納、過多的總結以及專案不建議使用的短語；
5. 每一項保留或新增的引用皆有依據，並核對每一項刪除的引用；以及
6. 在前後段落可用時，與前後段落的流暢銜接。

若專案具備文風或術語規範檔，即使在輕量模式下亦應套用。將確定性的發現視為情境判斷的提示，但切勿默不作聲地忽視。若通過此關卡後有更動任何文字，必須針對新的確切候選版本重新執行受影響的檢查。

這些檢查取決於所要求的操作：實質段落檢視會檢驗保留的支持依據；僅限文法的校正則維持原樣未變且已核實的支持依據，不聲明進行了新的引用審查。將整個章節的功能應用於章節工作，而非套用到每個孤立的句子。請指明任何無法取得的脈絡或來源。

<a id="four-pass-review"></a>
## 四輪檢視

整篇論文／投稿文件的檢視請使用完整的審視輪次。在大幅修改的小節或章節及其受影響的相依項目中套用這些輪次；表面文字修訂請使用受限候選版本關卡。既有的專案狀態僅為脈絡，並非要求進行全面檢視的證據。

<a id="pass-1-argument-and-structure"></a>
### 第 1 輪：論點與結構

檢驗讀者功能、研究缺口、研究目的、問題、組織架構、段落開頭與研究貢獻。

<a id="pass-2-evidence-and-consistency"></a>
### 第 2 輪：證據與一致性

對照產出、樣本、單位、方程式、圖表、表格、引用、主張處理範圍與傳播影響來檢驗方法。

<a id="pass-3-scholarly-prose"></a>
### 第 3 輪：學術散文

首先穩定術語與縮寫。接著檢視完全重複、重複短語與句首、過度使用非技術詞彙、陳腔濫調、過長的連續名詞堆疊、模糊的強調詞、主詞不穩定、語法、時態、語態、符號標記以及段落之間的流暢度。保留必要的技術性重複，切勿將同義詞輪替作為表面修飾手段。修改後，在編輯後的確切候選版本上再次執行此輪檢視；編輯前文字的檢核結果不能作為修改後版本的保證。

<a id="pass-4-delivery-integrity"></a>
### 第 4 輪：交付完整性

重讀確切的交付成果。查核摘要、參考文獻、編號、必要聲明、追蹤修訂、註解、檔案名稱、算圖呈現、隨附檔案與發布狀態。

當第 4 輪揭露實質問題時，修正後應重新執行受影響的先前輪次。
