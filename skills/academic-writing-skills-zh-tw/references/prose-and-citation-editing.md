<a id="functional-transitions"></a>
## 功能性轉折

辨識引導讀者從一個句子或段落銜接至下一個句子或段落所必需的邏輯關聯：對比、延伸、限定、原因、結果、比較、回歸本研究，或是銜接至下一節的橋樑。盡可能透過主詞與動詞表達該關聯。僅在轉折詞能讓邏輯關聯更清晰時才使用轉折詞。

摒棄僅宣示思維推進的轉折，例如無具體說明的 `Moreover`、`Taken together` 或 `One line of work`。唯有在移除該轉折會遮蔽真實邏輯關聯時，轉折才具有功能性。不要要求每個句子都以連接詞開頭，且當實質內容句即可承載該關聯時，不要額外增加純粹作為轉折的獨立句子。

將句首框架（如 `Beyond X,`）視為語境檢視的提示，而非預設的論述推進信號。僅在 `X` 明確指出了下一個子句真正有所延伸的邊界時，才保留這些句型。若該句僅是增加另一種應用或證據類型，請直接陳述該內容，而不要刻意宣告論述的推進。

在段落交界處，請將前一段的結尾句、修改段落的起始句與結尾句，以及下一段的起始句作為一個完整序列連貫閱讀。確認修改後的段落發揮了自身的功用，且未過早承接下一段的工作。當段落銜接至編號的研究問題或目標時，請確切指明每個結尾片語是在為哪一個具體問題做鋪陳；不要依賴泛泛的研究缺口句。

在結果（Results）以外的部分也應套用相同的邏輯關聯檢驗。文獻分組必須確立目前仍欠缺的具體比較；背景必須為後續的設計選擇做鋪陳；討論（Discussion）中的意涵必須緊扣所報告的發現；限制條件必須明確指出受其約束所影響的推論。這些是面向讀者功能的範例，而非硬性規定的章節範本。若邏輯關聯已很明確，請予以保留。若欠缺證據，應揭示該缺口，而不是捏造一個聽起來言之鑿鑿的過渡橋樑。

當文獻段落包含多個範例時，應選擇有助於推進論點的證據排序，而非保留最初找到文獻的順序。一個實用的預設排序是：廣泛的領域背景、接著是更具體的應用、再到與本研究最直接可比的前人先例，最後是尚未解決的研究缺口。若按時間、方法、因果或對比排序能更好地契合段落功能，則應改用這些順序；不要將由廣到狹的推進順序強加在具有其他清晰關聯的證據上。

若文獻的主張能被準確陳述，可將具有相同證據功能的來源整合在同一個句子或子句中。當使用 `For example` 能釐清從寬泛主張走向具體證據的過渡時，可用它來引出代表性文獻集，但不要在每次引用前都重複使用舉例標記。若最相近的前人先例確立了比較的邊界，請將其置於研究缺口的正前方。作為診斷方法，可暫時移除文獻引用：剩下的正文讀起來仍應是一段層層推進的論證，而非一篇篇研究摘要的條列清單。

<a id="workflow-handoff-test"></a>
### 工作流程銜接檢驗

對於說明流程的段落，在修訂局部批註後，應檢視完整的目標單元及現有的邊界語句。在順序或依賴關係至關重要處套用此檢驗；概念上的比較或文獻綜合則毋需硬性改寫為流水線流程。依據修改幅度調整閱讀範圍：標點符號的編輯毋需重新審視無關的章節，但修訂段落的開頭可能會影響其與相鄰段落的銜接。

1. 辨識各段落面向讀者的功能。順著步驟追蹤資訊流：有哪些可用資源、什麼操作使用了它、產出了什麼，以及該輸出接著在何處被使用。當讀者需要的是操作流程時，僅列出組件清單是不夠的。
2. 檢查每一組受影響的相鄰句子。陳述第二句增加了什麼，並在正文本身中指出其與第一句的連結。解決不明確的執行主體、指涉對象、前置條件或未加說明的換主詞情況。在每個段落交界處，檢查前一段結尾是否為下一段開頭做好鋪陳；若某項細節的位置打斷了該連結，請予以挪動。當開頭已具備過渡銜接時，切勿添加多餘的過渡句。
3. 區分初始的使用者配置與執行過程中的重複動作。例如，選擇模型接收哪些變數，與在每個時間步更新其數值是不同的。當混淆兩者會錯誤描述使用者工作流程時，應明確指出執行者與頻率。若來源未確立這些資訊，應記錄該缺口，而非憑空捏造手動操作、自動化或執行時程。
4. 保留真實的分支情況。區分循序步驟、可選的增補項、推進的前置條件、診斷性評估，以及改變或終止執行的操作。切勿將資料依賴性轉變為同時執行、將診斷轉變為自動否決，或將時間順序轉變為因果關係。應根據所提供的方法確立這些事實；範例無法提供缺失的實作證據。
5. 依據有支持的關聯來選擇連接詞。`Then` 可標示後續步驟；`once` 或 `after` 可標示前置條件；`if` 則引入條件。在有助於讀者理解時應予以保留。避免硬性規定連接詞配額、機械性替換同義詞，或在每個句首皆放置連接詞。
6. 以一般研究人員的步調閱讀最終文字，並僅憑內文轉述該路徑。檢查目標領域的讀者在不知曉起草討論的情況下，能否辨識輸入項、操作、輸出項及分支後果。修訂剩餘的最小阻礙，並在最終字詞修改後，重新閱讀受影響的部分。

<a id="worked-example-daily-forecasting"></a>
#### 實作範例：每日預報

這是一個假設性的教學範例，並非針對實際套件的主張。假設來源確立了以下事實：使用者在執行前選擇輸入變數；變數數值每日更新；預報使用完整的輸入數據；缺失輸入會停止當日的計算；而在稍後與觀測數據進行可選的比較時，會記錄診斷結果而不會變更預報。

**修改前：** "At the start of each day, users define the inputs. The model calculates a forecast. An optional check compares it with observations. Missing inputs stop the calculation. Then the input values are updated."

**審查發現：** 開頭暗示了每日的手動配置。每日數值出現在需要它們的計算之後。缺失輸入的條件出現在預報之後，且診斷的後果未予說明。添加 `then` 並不能修正這些錯誤。

**修改後：** "Users first select the input variables supplied to the forecasting model. Their values are updated each day. If required inputs are missing, that day's calculation stops; otherwise, the model uses the updated values to calculate a forecast. Once observations become available, an optional comparison records the difference between the forecast and observations without changing the forecast."

**驗收依據：** 修改後的路徑為「配置 -> 每日數值 -> 預報」，其中缺失輸入條件置於完成計算之前，且稍後可選的診斷與預報生成保持區隔。此變更保留了假定的來源事實；但並未確立真實實作即依循此流程。若既有文本已經清晰，且在未使用這些特定連接詞的情況下表達了相同的關係，應予以保留。

<a id="function-preserving-concision"></a>
## 保留功能的精煉

將每個句子對應至一個或多個必要功能：主張、證據、解釋、限定、綜合或過渡橋樑。在刪除科學實質內容之前，先移除或合併重複的功能。壓縮重複的範例、平行的文獻清單與重述的標準，同時保留精確的主張、其證據、推論界線與過渡橋樑。

僅將字數、句數以及與相鄰段落的比較作為診斷依據。不要強加統一的目標值。若較簡短的版本刪除了必要的比較層級、文獻引用、限制條件或轉折，它就並非更好的版本。

對於已被接受、已提交或經指導教授編輯的基準版本，請進行能解決實際問題及其依賴關係的最小修訂。保留運作良好的原始措辭；不要僅為了風格統一而改寫相鄰句子。若必須進行較大的結構性變更，在編輯前應先確認被更動的功能及其移放位置。批註標籤僅標示為因應某項要求所作的修改，而非涵蓋討論同一主題的所有段落。

當批註僅選取該基準版本的局部時，請使用 [comment-scoped-revision.md](comment-scoped-revision.md) 來確立實際的當前錨點與完整批註討論串、保留未選取的措辭，並為任何必要的延伸修改提供正當理由。為了連貫性而通讀整段並不代表獲准重寫整段。較舊的範例僅用於引導論證或風格；請使用當前的事實與數據，而非範例本身的研究主張。

在精煉之後檢查句子節奏。當極短的句子僅是為了表達 `Overall`、`However` 或 `The results are mixed` 時，應予以合併；當短句承載了必要的強調或完整的實質發現時，則予以保留。避免為了化解行文稠密而製造出一連串零碎短句。

<a id="natural-scholarly-prose"></a>
## 自然的學術行文

偏好使用具體的學術主詞、直接的動詞，以及目標領域讀者能辨識的術語。每個概念保持單一術語，避免同義詞輪替。透過讓每個句子說明某個研究群組探討了什麼以及它如何推進該段落的論述，將文獻清單轉化為層層遞進的論證。

為目標期刊廣泛的學科讀者寫作，而不僅是針對狹窄主題的專家。當讀者必須先解讀非必要的概括性標籤才能理解該主張時，應定義或替換該標籤。例如，當災害週期的各階段在分析上並不重要時，應對防救災相關任務進行具體描述，而非使用 `disaster management cycle`。

隨時保持清晰的讀者意識。為目標學術讀者寫作，切勿假定讀者已熟悉本研究的特定概念、體制、模型邏輯、專案標籤或數據處理選擇。對於跨學科研究，應假定讀者具備重疊的廣泛研究知識，而非精通每個環節的專業知識。在讀者初次需要處介紹必要的背景並解釋術語的作用；僅拼寫出縮寫的全稱並不能提供足夠的理解。簡明平實的語言旨在保留科學意涵與限定條件，而非使文字流於隨意。

依據前置知識引導讀者，而不僅僅是提供縮寫定義。在說明群組差異之前先介紹相關背景或制度規則，並在使用群組差異的模型設定之前先介紹這些差異。在每個步驟提供足夠的解釋，使下一段陳述能夠被理解；避免將實作細節引入背景中，或暗示某個缺乏所需特性的模型落實了現實世界的要求。

檢查讀者的認知負荷以及首次定義。即使正確展開了數個縮寫，句子所比較的實體或關係仍可能變得模糊不清。保留必要的既定術語；在重複的簡寫迫使讀者費力解讀清單處，改用其具體角色或清晰的組別名稱。不要將重新命名構念、輪替同義詞或再次機械性展開每個縮寫當作解決方法。

偏好使用明確的行動者、動作與比較參照對象。當語意不清時，請探問 “higher than what?”、“which difference?”、“whose loss?” 及 “what is the denominator?”。必要時將模糊的 `this difference` 或 `these limits` 替換為具體的結果或限制，而毋需重複整個定義。簡明平實的學術語言所簡化的是句法與資訊呈現順序，而非科學上的實質區分。

使主要行動者與動作保持清晰可見，而非將其埋沒在冗長的名詞堆疊或一連串的修飾限定中。在有助於讀者理解關聯時，先介紹已知資訊再引入新資訊。當過載句子的語意需要讀者反覆回讀時，可調整順序或拆分句子，但必須保留必要的專業術語、比較與不確定性。切勿強設字數上限，或用互不連貫的碎片句去替換一個稠密的句子。

例如，當句子涉及選擇時，將 `flood adaptation decision-making process` 改為 `flood adaptation decisions` 可能更清晰；若涉及過程，改為 `how households choose adaptation actions` 可能更合適。應依據語意進行選擇，而非依賴一成不變的禁用片語清單；切勿僅為了縮短名稱而抹殺過程與結果之間的區別。

<a id="plain-scholarly-language-across-fields"></a>
### 跨領域的簡明學術語言

目標是讓來自其他領域且具備科學素養的讀者，在不了解本研究內部簡稱的情況下，也能理解核心主張。這是一個可及性目標，並非保證所有潛在讀者在缺乏背景知識的情況下都能跟上專業推導。保持學術精確性；簡化通往該主張的論述路徑，而不是用模糊或更強烈的主張來取代它。

1. 透過清晰可見的主詞與動詞陳述行動者或單位、測量概念及主要關聯。在符合段落功能時，將研究發現置於從屬細節之前，但切勿置於理解該發現所需的定義之前。報告差異時應明確指明比較基準；切勿讓讀者僅憑子圖順序或變數標籤去猜測。
2. 在讀者閱讀需要之處提供最低限度的前置條件。保留必要的專業術語，並簡要說明其在本研究中的意涵或作用；僅展開縮寫全稱未必有幫助。在獨立段落中，若理解該主張需要用到新縮寫或不熟悉的統計標籤，應展開縮寫並加以解釋。例如，當所測量的數量是物種豐富度時，將其定義為觀察到的物種數量。將定義寫在易讀的子句中，而非使用掩蓋主詞的巢狀修飾語。避免使用較寬鬆的日常同義詞取代已定義的構念，或添加教科書式的枝節討論。應陳述缺失的背景脈絡，而非捏造定義。
3. 保留決定該主張的分子、分母、單位、時間、母體、條件與不確定性。百分點差異不等同於相對百分比變化；正規化損失不等同於家戶福祉。若簡短的文字刪除了這些區分或改變了比較基準，那就是失敗的改寫。
4. 既保留有支持的因果主張，也保留其局限性。切勿將觀察到的關聯轉變為因果效應、將不顯著的差異轉變為相等，或將測得的中介結果轉變為未測量的最終端點。反之，切勿機械性地將隨機對照設計所確認的效應削弱為僅僅是關聯。在不增加未經測試的機制或新證據的情況下解釋結果的意涵；在有必要防止可能誤讀時，指明不能得出什麼結論。
5. 修改完成後，在不查閱隱性起草歷史的前提下進行「盲讀」轉述：研究了誰或什麼、測量了什麼、發現了什麼比較或關係，以及該段落允許或不允許讀者得出什麼結論。找出支持每個答案的字詞並檢查修訂句子的語法。當答案需要仰賴未經解釋的術語、指涉對象、分母或邏輯跳躍時，請進行最小幅度的修訂並重讀現有的相鄰句子。僅索取解決所請求主張所需之資訊。切勿在描述性比較中預設存在干預，或僅為了提供局部臨時修改而索取周圍文本；無法取得相鄰文本會限制對行文流暢度的主張。僅評估所請求的單元及受影響的依賴項。

請將此檢查與句長或易讀性評分分開處理。獨立讀者視角的評估可以發現剩餘的理解問題，但模型流暢的轉述並不能作為各領域真實讀者皆能理解的證明。在測試中，除了核心要旨外，應對比確切的來源事實與修改內容；切勿獎勵改變了科學意涵的較短措辭。

在進行明確的獨立審查或屢次出現讀者理解困難時，請使用 [independent-reader-review.md](independent-reader-review.md) 區分初次使用時的已知資訊與稍後提供的定義。其盲讀審查結果補充了這些局部的正文檢查；它們並非要在每次編輯中都強加額外的代理人。

<a id="unpack-noun-chains-by-meaning"></a>
### 依語意拆解名詞鏈

在起草與限定範圍的正文審查期間，應標記在核心概念周圍堆疊多個修飾詞並迫使讀者猜測其關係的名詞片語。四到五個堆疊的名詞是一個強烈的審查提示，而非放諸四海皆準的字數限制；較短的片語同樣可能含混不清。在不將局部編輯擴大為全篇文件審查的前提下，將相同的檢查套用至受影響的標題、圖題與表格標籤。

1. 辨識核心概念與預期的關係：是誰的、什麼對什麼做出反應、測量了什麼、涵蓋了什麼，或是某項行動是為了什麼。使用所提供的背景脈絡或定義；若關係仍未確立，請提出具針對性的問題或提供明確帶有條件的備選方案，而不是默不作聲地自行選定一種。
2. 使用所有格、合適的介系詞或包含主詞與動詞的子句，將這些關係明確表達出來。例如，在合乎預期語意時使用 `responses to a policy`、`coverage for contents` 或 `the wellness of households`。切勿機械性地插入 `of`、`for` 或 `to`；`wellness to ...` 並非通用的修復模式。
3. 保留已確立的專業術語、專有名詞、既定構念及清晰的慣用複合詞。切勿混用 wellness、well-being、welfare 與 willingness，或將意願（willingness）的測量改變為觀察到的行為。保留限定條件、比較組別、單位、時間與不確定性。添加連字號或輪替同義詞並不能釐清隱蔽的關係。
4. 重讀整個句子及其局部語境。確認讀者毋需回讀即可辨識該概念與關係，且該修訂未增加因果關係、未改變測量指標，亦未製造出另一個稠密的片語。

將這項語意檢驗同樣套用至簡短的比較標籤。在正文中，當讀者無法辨識比較的是哪些組別或何種數量時，`group mean differences` 便是不完整的。應指明人員或資料來源、所測量的概念以及比較對象，然後以主詞與動詞表達該關係。若明確的統計術語或表格標題在該閱讀邊界處其組別與數量已經十分清晰，則應予以保留；作者在某篇論文中拒絕某個片語，並不代表全面禁用平均值比較。

不要將所有格視為充分的修復手段。`Human respondents' insurance willingness` 仍可能掩蓋受訪者究竟願意做什麼。當有相應關係支持時，偏好使用 `human respondents reported willingness to buy insurance` 或 `willingness to buy insurance among human respondents`。若該發現屬於比較性質，應保留誰與誰進行比較；切勿在簡化行動者時省略了比較對象。在採納修訂之前，應與來源對比方向、量級、統計顯著性、等價性以及因果強度。將不顯著的差異與平均值相等明確區分開來，並將陳述的意願與實際的購買行為明確區分開來。

僅在陳述的語意獲得確認時，才使用這些假設性的修復方案：

- `renter flood insurance purchase willingness` → `renters' willingness to buy flood insurance`，當該構念為意願而非投保加入時。
- `human insurance policy responses` → `people's responses to insurance policies`，當政策是人們所回應的對象，而非收集其回應的單位時。
- `insured household wellness scores` → `wellness scores for insured households`，當 wellness 是本研究定義的構念，且納保家戶為評分母體時。

<a id="other-local-prose-checks"></a>
### 其他局部正文檢查

依功能使用時態：已完成的流程與觀察通常使用過去式，而圖表描述與當前的解釋則可使用現在式。在適當情況下使可比較的子句保持一致，但不要強求摘要（Abstract）、結果（Results）與結論（Conclusion）採用單一時態。即使是在經指導教授編輯的文本中，修復語法錯誤也應採用保留原意的最小修改；保留基準版本並不代表將錯誤認證為正確。

當學術慣用動詞未增加任何實質意涵時，偏好使用字面本義的動詞。若 `draw on data` 僅代表 `use data`，請寫作 `use data`；僅在 `draw on` 能傳達使用 `use` 就會流失的更廣泛學術或證據依賴關係時，才保留該用詞。將相同的檢驗套用至其他聽起來優雅的片語，而非機械性地輪替它們。

在閱讀時兼顧語法與節奏感。標記重複的句型、過度的平行列表、冗長的名詞堆疊、模糊的行為主體（例如在學術領域或證據來源更明確時仍使用 `researchers` 或 `studies`），以及重複的指示代名詞句首（如 `This`、`These` 或 `Such`）。僅在修改能改善語意、流暢度或證據連結時才進行修訂。

<a id="sentence-pattern-variety-without-changing-logic"></a>
### 不改變邏輯的句型多樣性

將穩定的論證順序與重複的語法支架區分開來。一段文字可能正確地依序呈現「發現 → 證據 → 解釋」，卻不必要地重複相同的句型。審視句首族群，而非僅檢查完全相同的字串：即使動詞不同，`We first ... / We then ... / We next ...`、`These results show ... / These findings indicate ...` 或重複的 `By ... , we ...` 子句聽起來仍可能顯得單調重複。

進行段落層級的工作時，請檢視整個段落及其可參考的相鄰段落。進行小節或章節層級的工作時，還應依序閱讀各段的開頭與結尾，以檢查是否存在重複的句式支架。單一句子的語法修正並不代表獲准為了多樣性而重寫相鄰段落。確定性掃描會將段落內三個相鄰的流程性 `We` 框架標記為審查提示；它並不會剖析所有句子結構、設立通用配額，或認證更廣泛的文體多樣性。

保留實際的順序、依賴關係、專業術語、行動者與比較基準。在有助益的情況下，可合併相依步驟、將相關數據或結果作為主詞，或刪除未增加任何資訊的順序詞。切勿僅是將 `then` 輪替為 `next`、將每個句子都改成被動語態，或為了避開重複而替換已定義的專業術語。當刻意的平行對稱有助於讀者理解對等比較與流程順序時，應予以保留；請記錄保留的原因，而非將診斷提示直接當成自動判定錯誤。

例如，以下假設性措辭可以在不改變流程的情況下進行修復：

- 修改前：`We first fit the income distributions. We then sample incomes from these distributions. We next calculate losses relative to income.`
- 最小修訂：`We fit the income distributions and sample incomes from them. The sampled incomes are then used to calculate losses relative to income.`

謹慎使用句首的 `Beyond X,` 與 `Taken together,`，切勿將其作為預設的過渡橋樑或總結。偏好直接點名新增的證據、實際邊界或綜合發現。當 `Beyond X,` 確立了實質的延伸時予以保留，當句子確實綜合了不同證據時保留 `Taken together,`。切勿機械性地以另一種套話連接詞來替換它們。如 `floodwater extended beyond the boundary` 這樣的字面措辭並不屬於套話轉折。這兩種句首形式都會接受語境診斷；專案特定的較強偏好仍保留於正文剖析設定檔（prose profile）中。

起草完成後，大聲朗讀該確切段落，或模擬研究人員在自然情境下會如何表達。檢驗標準不在於文字聽起來是否像口語對話，而在於句子能否以正常步調朗讀、其主詞與動作是否保持清晰，以及聽者能否依照資訊呈現的順序理解。若段落聽起來像生硬拼湊、需要反覆回讀，或包含研究人員不太可能說出口的措辭，請予以重寫。

<a id="gap-statements-and-comparative-framing"></a>
## 研究缺口陳述與比較架構

將主要任務動詞視為科學主張的一部分。唯有當動詞與研究實際的推論目的及分析相符時，才使用如 `compare`、`characterize`、`estimate`、`predict`、`validate`、`reproduce`、`replicate` 或 `evaluate` 等動詞。切勿僅因為較強勢的動詞聽起來更具重要性，就將描述性比較轉變為能力、驗證、等價或通過／失敗的主張。當研究探討兩種證據來源有何差異或如何對齊時，應直接陳述比較內容，而非暗示某個來源被預期要重現另一個來源。

將研究缺口撰寫為具體缺失的知識、證據、比較、機制、研究母體、尺度或分析層次。除非句子或相鄰語境確切指明了什麼尚未被檢驗，否則應將如 `remains unclear`、`is not well understood` 或 `little is known` 等片語視為不完整。在有文獻支持的情況下，偏好具體陳述文獻現況（例如 `has not been examined`、`has rarely been compared` 或 `remains largely unexamined`），同時避免提出檢索基礎無法支持的絕對新穎性主張。

避免將研究對象、結果、比較來源、母體、尺度與分析層次全塞進一個冗長的名詞堆疊中。將核心比較或未知事物置於「主詞－動詞」核心中，必要時再以獨立的片語或句子補充整體、子群、時間、空間或方法學的處理範圍。讀者應在讀完整個句子之前，就能辨識出究竟缺少了什麼。

在論文所能證實的層次上陳述該缺口為何重要：解釋、理論、方法選擇、政策推論、計畫設計、決策支援、可轉移性，或其他實質影響。其重要性可出現在同一句或下一句中；不要強求每個缺口句都必須包含它。當稿件可以直接指明仰賴該缺失證據的具體決策或推論時，請避免使用泛泛的重要性宣稱。

當相近的前人先例與本研究高度重疊時，應利用它來界定研究邊界，而非將其視為對新穎性的威脅。陳述該研究實際比較或確立了什麼，進而指出仍待探索的不同分析層次、結果、結構、母體或推論。若先前研究已涵蓋了某類比較的較狹窄版本，切勿宣稱 `no study` 完成了一大類比較。

<a id="claimcitation-alignment"></a>
## 主張與引用文獻一致性

將每個句子拆解為可獨立查核的主張。針對每項主張，指明支持它的引用文獻或稿件證據。句尾的一組文獻引用必須支持其看似涵蓋的每個實質子句；否則應拆分句子、縮小主張，或調整文獻引用的位置。

對於合併引用的文獻，請核實每個被引來源皆符合所指明的領域、方法、結果或限制。切勿僅因為某篇引用文獻曾出現在先前的草稿中就予以保留。當主張被精簡壓縮時，應重新檢查留存的引用文獻群是否仍能支持新的綜合論述。當從某段文字中刪除某項引用時，在更改參考文獻清單之前，請確認該文獻是否仍在其他地方被引用。

當主張仰賴文獻來源的具體細節時，切勿單憑標題或記憶來認證主張與引用文獻的支持關係。請在符合該主張所需的深度下閱讀原始文獻、摘要或權威記錄。將經核實的支持與看似合理的主題相關性明確區分開來。

當被引用的研究報告的關係方向與當前樣本或研究區域所校準或估計的相應關係不同時，切勿直接附上引用文獻而留下未加解釋的矛盾。在引用文獻之前或同時說明處理範圍的差異：此處報告的關係反映了當前的樣本或地點，而若被引證據支持該項限定，則該關係在其他母體、地點或環境中可能有所不同。保持此免責說明簡短且有證據支持。切勿將校準出的關係改寫為模型假設、暗示相反證據會自動使本研究結果無效，或憑空捏造文獻來源未支持的語境變異。若無法從現有證據中化解此差異，請陳述尚未解決的對比，並將其解釋保留給討論（Discussion）部分。

<a id="observable-stock-or-ai-like-prose"></a>
## 明顯的套話或 AI 風格行文

切勿從寫作風格推斷作者是否為 AI。僅報告可觀察到的特徵：空洞的後設話語、套話轉折、泛泛的綜合論述、重複的指示代詞句首、過度的預告與總結語言、對稱但內容貧乏的分類清單、重複的節奏、模糊的主詞，或缺乏支持的共識主張。

評估組合搭配與局部密度，而非單純禁用孤立的片語。常見片語偶爾出現一次可能很自然，但若連續出現幾個就會顯得公式化。僅在能更精確陳述實際關係或證據時，才替換該措辭。

將針對句首 `Beyond X,` 與 `draw on` 等形式的診斷視為讀者可及性檢視的提示，而非措辭有誤的證明。檢查讀者是否毋需先解讀轉折範本、領域標籤或間接動詞，就能陳述該句子的具體主張。

<a id="dash-and-hyphen-style"></a>
## 破折號與連字號格式

在編輯前區分三種情況：

1. 作為標點符號使用的句法長破折號（em dash）或短破折號（en dash）；
2. 複合修飾詞、專業術語、範圍或名稱中的詞彙連字號（hyphen）；以及
3. 懸空複合詞，例如 `subgroup- and topic-specific`。

不要強加全面禁令。當連字號能避免歧義、依循既定術語或專有名詞，或符合發表管道的語言慣例時，應保留複合詞。當該領域通常將其視為名詞片語且不會產生歧義時，偏好使用開放式複合詞（不加連字號）。當自然的片語更為清晰時，應改寫懸空複合詞以及多個非技術性連字修飾詞聚集的情況。

不要僅因為既定的開放式複合詞置於另一個名詞之前，就添加連字號。判定該複合詞的語法角色並核實其慣用形式；例如，在 `disaster management phases` 中保留 `disaster management`，而非自動寫成 `disaster-management phases`。當專案或發表管道確立了開放形式時，請將其註冊在 `style_profile.preferred_open_compounds` 中，以便精確候選版本審查能回報帶有連字號的變體。

在句子與段落層級檢視破折號的密度。即使語法正確，若多個破折號密集出現，仍可能干擾閱讀。檢查破折號是否掩蓋了一個本應調整順序或進行拆分的過載句子。

<a id="exact-candidate-procedure"></a>
## 精確候選版本程序

在最後一次字詞更動後：

1. 凍結該精確候選版本，並在支援時記錄其雜湊值；
2. 在所要求的深度與變更影響範圍下，針對該確切文本重新執行上述適用的審查；
3. 將前一段與後一段連同該版本一起閱讀；
4. 在語境中檢查每項確定性診斷，並記錄為何保留任何被標記的形式；
5. 將新增、刪除及受主張影響的引用文獻與參考文獻清單進行核對；針對實質性審查檢查留存的支持證據，而毋需在僅涉及語法的編輯中重新認證未更動的來源；
6. 針對該精確候選版本執行目標讀者視角檢查與大聲朗讀檢查；以及
7. 若事後更動了任何文字、引用或標點符號，則該審查失效。

若僅有較早的候選版本通過檢查，切勿稱該段文字為最終定稿、經潤色、自然、精煉或經引用查核。
