<a id="modes-and-lifecycle-stages"></a>
## 模式與生命週期階段

對於有明確邊界的文字工作，請使用輕量模式。對於持續的稿件整合、附隨成果協同處理或發布認證，請使用受管專案模式。既有的受管專案會為局部編輯提供授權與決定；但不會擴大原本要求的審查範圍。

除章節發展外，亦應辨識以下出版狀態：探索性草稿、完整內部草稿、初次投稿、修訂後重投、已接受稿件以及校樣。隨著狀態推進，應縮小介入範圍。在校樣階段，僅進行為確保準確性、排版製作或符合發表園地規範所必需的授權更正；未經明確許可，切勿重新更動已定案的結構或文風。

應區分三種時間軸：

- **寫作順序：** 作者撰寫各章節的先後順序
- **證據依賴性：** 後續的分析會限制前期的架構設定與後續的摘要總結
- **審查成熟度：** 發展階段、實質階段、整合階段與投稿階段

切勿將某個章節標記為永久完成。請將其標記為相對於特定已指名證據狀態或發布候選版本的最新狀態。

將 [execution-and-acceptance.md](execution-and-acceptance.md) 中的階段核檢表用於寫作計畫、編輯後檢核、章節結尾檢核以及四輪審查的證據檢驗。請重複使用同一份專案紀錄；核檢表應隨任務而變動，而非隨對話階段變動。

對於未宣告其他順序的傳統實證論文，請遵循：研究定位 → 延伸證據大綱 → Introduction → 研究脈絡 → Methods → Results → Discussion/limitations → Conclusion → 重建 Abstract。若有適用的不同文類或作者要求，請依其規定；章節編號與六大標題並非通用要求。補充資料應與 Methods 及 Results 同步撰寫，並在整合階段進行比對一致化，而非事後才草率補充。

在依發表園地進行大綱擬定或格式設定前，應建立或重複使用 [overlay-contract.md](overlay-contract.md) 中的發表園地設定檔。應將科學問題／貢獻與期刊方向及讀者群的比對，與論文類型、特定階段格式及文風的檢核分開進行。處理範圍相符並非新穎性或獲接受的證據；兩者不合是作者應做的決定，而非擅自更改研究的授權。在整合階段，應對照現行的官方來源重新檢核受影響的規範，而非僅依賴已發表的範例。

<a id="scope-and-check-depth"></a>
## 處理範圍與檢核深度

沿著四個獨立軸向進行路徑導向：**行動**（例如文法更正與科學審查的區別）、**文本處理範圍**、**變更影響**，以及**驗證深度／資料來源可用性**。整份檔案的標點符號編修並不等同於完整的科學審查；單一句子中的指標變更可能就需要跨檔案檢核。

在各處理範圍均應採用通用核心原則：確認已獲認可的來源與授權、保留原意、檢驗相關的讀者功能與主張界線、保持術語／比較的易讀易解性，並檢查確切的候選文本。僅在適用之處增加下列檢核：

| 要求的單元 | 附加檢核 | 切勿推論出 |
|---|---|---|
| 句子或純文法編輯 | 文法修復、科學意涵未變更、局部指涉與符號表示 | 有權重構論點或為引文背書認證 |
| 段落 | 功能、主張與證據關係、意涵、前置條件、局部術語、前後文脈絡 | 全文稽核或必須有結尾口號標語 |
| 小節 | 段落角色與順序、缺失／重複的功能、相關圖表／數據、累積實質回答 | 每一張圖表都必須能獨立證明整個研究問題 |
| 章節 | 小節之間的連結、章節目的與研究問題涵蓋範圍、方法／發現／詮釋的配置、結尾盲點檢核 | 對無關章節進行全面審查 |
| 整篇稿件 | 缺口–問題–方法–結果–詮釋–結論鏈；摘要、術語、文獻參照、數據、視覺圖表 | 驗證無法取得的原始證據或排除在外的隨附檔案 |
| 投稿文件 | 所選稿件、補充資料、回覆意見與交付標的；承諾事項、標籤、編號、穩定行號參照、修訂標記／乾淨狀態、完稿呈現 | 未選取或未檢查之檔案的備妥就緒狀態 |

實質的局部審查會檢核支持該局部主張的文獻引用與數據。純表面編輯則保留既有且未變更的佐證；若發現重大的實質錯誤應予標記，切勿擅自捏造修復方案、暗中擴大為執行模型，或聲稱已完成全面稽核。當缺乏脈絡或資料來源時，應將可用的語言編輯與未核實的科學斷言明確區分開來。

完成時，應將涵蓋範圍回報為：已檢核、不適用、超出所要求的處理範圍，或資料來源無法取得／未核實。局部的檢核在處理範圍內可能已屬完整，但這並不代表整篇稿件均已備妥就緒。

<a id="reader-function-mapping"></a>
## 讀者功能對應

在套用結構規則前，應先將實際章節對應至讀者功能。

| 讀者功能 | 實證論文 | 文獻綜述或綜合分析 | 架構或方法論文 | 理論或概念論文 |
|---|---|---|---|---|
| 問題與缺口 | 緒論 | 緒論 | 需求與限制 | 問題與概念缺口 |
| 證據來源 | 研究脈絡與資料 | 檢索與篩選 | 需求與輸入 | 既有理論或前提 |
| 分析流程 | 方法 | 綜合分析方法 | 架構或演算法 | 論證或推導 |
| 主要貢獻 | 結果 | 證據綜合分析 | 驗證或應用 | 命題或意涵 |
| 詮釋 | 討論 | 討論 | 評估與意涵 | 邊界條件 |
| 最終綜合結論 | 結論 | 結論 | 結論 | 結論 |

當特定文類以不同方式提供相同功能時，請勿強制要求使用諸如 `Study Area`、`Methods` 或 `Results` 等標題。

<a id="review-maturity"></a>
## 審查成熟度

- **發展階段：** 檢驗缺口、目的、架構、缺失功能與方法可行性。
- **實質階段：** 檢驗證據對齊度、方法完整性、技術精準度、術語與圖表。
- **整合階段：** 檢驗跨章節傳遞、詮釋、研究限制、摘要總結以及剩餘阻礙。
- **投稿階段：** 檢驗確切檔案、中繼資料、參考文獻、格式編排、完稿呈現與發表園地規範。

對於修訂後重投，應將審稿者的每項要求對應至變更後的證據與回覆產物。對於已接受稿件與校樣，應將作者名列、結果、方程式、文獻引用與製作端中繼資料視為受保護的高風險欄位。

審查成熟度並不等同於章節順序。若 Results 變更了獲得支持的主張，請在整合階段重新檢視 Introduction。

<a id="stage-gates"></a>
## 階段關卡

<a id="project-and-outline-gate"></a>
### 專案與大綱關卡

應確認進行中的專案、資料來源、原型、目標讀者、缺口、研究目的或問題、產出、貢獻以及非主張事項。確保每個規劃的研究問題都具備合理的證據途徑。

應將延伸大綱建構為證據計畫，而非僅是標題列表。針對各章節與規劃的段落，應記錄其讀者功能、核心主張或問題、獲授權的證據、推論界線，以及通往下一單元的銜接橋樑。在開始撰寫散文草稿前，應由上而下（從缺口到貢獻）以及由下而上（從現有證據到獲支持的主張）檢驗大綱。

對於新草稿，應使該計畫呈現為一系列規劃的段落主題句，各主題句均附有相應的證據位置與必要的限定條件。在不含佐證細節的情況下通讀該序列：它應能說明研究的推展歷程，而非僅僅列出主題名稱。對於缺乏佐證的發現，應標記為證據需求，而非已確立的結果。應採用該文類的讀者功能，切勿將實證標題強加於概念性或理論性論文之上。

對於既有草稿，應擷取所要求章節的實際開頭句，並註明各段落所履行的功能，藉此進行逆向大綱分析。若開頭句隱匿或誤述了重點，應記錄該不一致之處，而非暗中以理想化的摘要取代。應檢核是否有功能缺失或重複、過早引入細節以及缺乏支撐的轉折；並針對受影響的最小幅度段落進行修復。純文法編輯不會觸發章節的逆向大綱分析，且這兩項操作皆不需要建立新的專案檔案。

<a id="paragraph-and-section-drafting-gate"></a>
### 段落與章節撰寫關卡

起草每個段落時，應依循五部契約：功能、主張、證據、開展與銜接橋樑。應於局部範圍並結合可取得的相鄰文本進行檢核。對於小節／章節的工作，亦應依序通讀主題句。在完成最終重寫後，套用適當的確切候選文本檢核；後續任何字詞變更都會使受影響的檢核失效。一個章節並非僅因所有規劃段落皆已存在就代表處於最新狀態；其各段落必須構成一個累積推進的論點，且不含重複的功能、孤立無援的證據或缺乏支撐的轉折。

<a id="context-and-methods-gate"></a>
### 脈絡與方法關卡

追溯資料或前提：從來源經過準備、測量、模型或分析、診斷以至產出。應將具可重複性的程序，與脈絡描述及後續詮釋明確分開。

<a id="results-gate"></a>
### 結果關卡

從已驗證的產出建構研究發現。針對每項比較，應確認參照群組、情境、環境設定或時間點，回報必要的結果，然後說明觀察到的模式對研究目的或問題所代表的意義。單純的數據並非實質的回答。應在段落或小節的功能有所需要時加入詮釋，而非在每張圖表後都加上例行公事般的結尾句。暫時移除 SQ/RQ 標籤：剩餘的陳述仍必須具備回答問題的實質內容。Results 可描述分析直接支持的分解結構或關聯性。基於文獻的解釋、未經測試的機制、替代解釋以及政策意涵應置於 Discussion 中。應找出未產生任何回報結果的孤立方法，以及未描述任何方法的孤立結果。

<a id="discussion-gate"></a>
### 討論關卡

明確區分直接發現、獲支持的機制、詮釋、替代解釋、意涵與推測。說明各項研究限制如何改變推論或通則化能力。

<a id="conclusion-and-summary-gate"></a>
### 結論與摘要關卡

綜合現有證據；切勿直接複製前期的摘要。保留研究任務與處理範圍。切勿引入新證據，亦不可暗中將比較升格為驗證。

<a id="companion-and-release-gate"></a>
### 隨附資料與發布關卡

同步檢查補充文件、圖表、表格、中繼資料、封面／附隨資料與儲存庫聲明。檢查確切的使用中檔案，若仍存在必要證據缺失或高嚴重度問題，應阻擋發布。

<a id="top-to-bottom-integration-gate"></a>
### 全文由上而下整合關卡

在所有主要章節皆已齊備後，以四個截然不同的通次審查確切的稿件：論點與結構；證據與處理範圍；學術散文文風；交付完整性。在散文文風通次中，審查術語、縮寫使用、字面與語意重複、陳腔濫調、句子與段落開頭、主詞連貫性、舊到新資訊流以及銜接轉折。每當散文編輯變更了科學意涵或主張處理範圍時，必須重新執行受影響的先前通次。

<a id="chapter-closure-blind-spot-check"></a>
## 章節結尾盲點檢核

在每次章節完成或進行實質章節修訂時，在常規撰寫檢核之後，即使未出現明顯問題，亦應重新審視該章的推論過程。執行的時機是強制的；診斷內容則取決於實際的研究設計、主張、資料來源以及所要求的處理範圍。僅針對標點符號的通次並不等同於章節完成或實質審查。

從章節指南與研究設計轉接器中挑選適用的問題：

- Introduction/脈絡：所選案例與實際證據的處理範圍是否符合承諾的研究任務？前置條件是否安排在相依設定之前，以及選樣是否被誤認為具代表性？
- Methods：來源、應用假設與評估是否界線分明？所描述的操作能否在沒有隱含的移轉、相依性或聚合假設下，支持所承諾的推論？
- Results：組成成分、分母、操作順序或比較條件是否可能改變其意涵？因果解釋是否獲得規則或相關性以外的充分支持？
- Discussion/研究限制：在延伸推展中究竟有何者保持穩定，以及各項限制縮減了哪項推論？狹隘的指標是否被泛化為更廣泛的構念？
- Conclusion/Abstract：內容壓縮是否遺漏了條件、比較對象、主體、處理範圍或限定語句，或是誇大了因果／驗證強度？

應靈活調整而非生搬硬套範例：質性研究可能需要反例與可轉移性檢核；理論研究需要前提與反例檢核；綜合分析則需要涵蓋率與異質性檢核。僅重新檢視相關的相依關係；缺乏證據並不等於無效的證明。記錄實質發現以及已檢核／不適用／超出處理範圍／未核實的界線，無須為每個段落都建立流水帳。這並非保證已找出所有未知的未知。

<a id="change-impact-classes"></a>
## 變更影響等級

| 等級 | 範例 | 最低限度重新檢核 |
|---|---|---|
| A: 語意契約 | 缺口、子問題、產出、任務動詞、貢獻 | 整體證據鏈；標題、摘要、亮點、結論、投稿摘要 |
| B: 證據或方法 | 樣本、模型、分析、數據、圖表、研究限制 | 來源以及受影響的 Methods、Results、詮釋、視覺圖表、補充資料、摘要總結 |
| C: 中繼資料 | 作者、角色、資助、所屬機構、聲明事項 | 載有這些項目的各項投稿產物中受影響的欄位 |
| D: 表面修飾 | 文法、標點符號、格式排版 | 局部語意差異、受保護脈絡、完稿呈現 |

當單一編輯包含多個等級時，應套用最高影響等級的重新檢核，加上各項產物特定的檢核。

應依據相依性觸發條件而非檔案大小，來擴大局部檢核的範圍：

- 定義／縮寫變更 → 受影響的用法與獨立閱讀的產物；
- 指標、分母、單位或數值 → 受影響的繪圖、圖說標題、結果、詮釋與摘要總結；
- 方法／機制變更 → 實作／設計描述、證據、假設與推論界線；
- 研究問題或核心結論變更 → 完整的證據鏈與摘要總結；
- 文獻引用增刪或主張變更 → 來源佐證、其他用法、參考文獻清單條目；
- 僅文法／標點符號 → 局部語意差異與相關格式檢核。

若觸發的相依關係超出寫入授權範圍，應在許可情況下進行檢視並回報所需變更；切勿暗中編輯。當相關輸入未變更時，請重複使用現有的已驗證證據。
