<a id="conclusion"></a>
## 結論

綜合歸納 **該研究做了什麼 → 確立了什麼 → 增添了什麼貢獻以及適用於何處**。採用如 “This study examined…” 的直接開頭是有效的。當 “aims to” 能準確陳述目的時即可使用；請以適當的時態報告已完成的工作。在表明該研究身分之前，毋須重新撰寫包含重要性–缺口–目的的引言。

陳述方法與研究任務、研究對象或系統，以及相關的地點、時間或分析處理範圍。僅提及某個架構的名稱並不等於解釋了它是用來調查什麼。請保留實際的任務動詞，並區分開發方法、示範應用、比較群組以及驗證預測。

在為實質總結修訂挑選句子前，先從當前的引言、已核准的大綱與作者需求中找回研究的主體定位。在現有的寫作計畫中，區分**目標**（該研究試圖增進何種理解或改善何種決策）與用於解決該目標的**工作**。僅在研究設計支持之處，才具名指出被研究的實體、比較基準、維度以及總體/子群組層級。切勿將方法、模型比較、招募平台或示範區域變更為替代目標。未列出編號問題的論文仍有其研究目的；切勿為了表達目的而憑空捏造次要問題（SQs）或固定數量的句子。

遵循所要求的段落功能。若開頭段落說明了該研究做了什麼，而後續段落綜合歸納研究發現，請保持這兩種角色的區隔。保留原本已清晰的開頭與可用的作者語句；僅修補缺失的關聯或處理範圍。教授過去的範例提供的是風格參考，而非當前的樣本數量、群組名稱或已核准的措辭。

區分招募族群、研究地點、背景情境與示範案例的角色。更正地理描述時，切勿刪除科學目的，亦不可將已知邊界隱藏在 “study context.” 之後。若僅在總體層面檢驗測量品質，而子群組工作僅涵蓋分佈與關係，則不可將每個總體維度擴展至每個子群組。請參閱 [evidence-context case 12](evidence-context-cases.md#12-research-identity-before-sentence-compression)
以取得假設性範例與維持不變的對照組。

依據研究問題或分析順序來綜合歸納答案，而非逐一重述每張圖表。保留主要對比、比較基準、方向以及對語意至關重要的任何條件。描述機制時，其強度僅限於分析所支持的程度。以主要的 Results 作為證據基礎，並以 Discussion 進行限制與限定；切勿僅因其聽起來更廣泛，就引入新發現或將延伸分析提升為頭條標題。

結尾應提出由這些答案支持的具體貢獻、意涵或應用邊界。政策可行性與負擔能力的主張需要相關證據；單純比較損失並不能確立這些主張。不強制要求固定的段落數量。切勿照抄摘要、強加宏大的政策建議，或將可用選項的數量等同於其實際成效。

<a id="abstract-identity-and-information-functions"></a>
## 摘要主體定位與資訊功能

依據已穩定的稿件重新建構摘要，而非依據過時的概要。使讀者在沒有圖表、內部代碼或起草歷程的情況下仍能理解該研究。請依據體裁與已核實的發表管道限制，以適當的密度提供以下資訊功能：

| 功能 | 讀者應了解的內容 |
|---|---|
| 問題或科學需求 | 哪種理解或決策至關重要，以及缺失了哪些相關知識。 |
| 目的 | 本研究調查、開發、估計、比較或確立了什麼。 |
| 方法及其角色 | 哪種方法產生了證據，以及該方法實際發揮了什麼作用。避免列出沒有說明目的的技術名稱。 |
| 研究對象與處理範圍 | 研究對象為何，以及解讀該答案所需的地點、族群、資料集、時間區間或設定環境。 |
| 主要發現 | 有支持依據的實質答案、具名比較的項目、方向或幅度，以及關鍵的限定條件。 |
| 貢獻與邊界 | 增添了何種新理解，以及該主張得以成立的處理範圍。 |

這些是資訊功能，而非六個強制性的區塊或固定的句子數量。自然流暢時可將其合併，或遵循已核實的結構化摘要格式。研究背景並不必然是地理試驗場域：它可以是實質研究對象、選定的樣本、理論領域或評估資料集。切勿僅因使用了某個案例進行示範，就主張具代表性或通用性。

在首次相關使用處解釋必要的專門術語，即使正文稿件中已對其進行定義。當目標讀者群理解時，請保留標準術語；替換不必要的內部簡稱。平實的描述（例如 “losses after insurance payouts”）可伴隨已定義的產出結果出現，而不改變其意義。保留理解主要發現所需的比較基準與事件/時期條件。

切勿為了填補範本而捏造最佳化目標、代理人動機、回饋機制或數值結果。應從當前的引言與已接受的研究定位中推導科學動機。僅在無法從這些來源解決重大缺口時才提出詢問；切勿在每次改寫前都要求使用者重複已提供的 “why”。

<a id="rules-versus-preferences"></a>
## 規則對比偏好

這些功能並未衍生出通用的字數或句數上限、單一段落要求、固定開頭、強制置中的研究區域、禁用原始數值、禁用連接詞或禁用標點符號的規定。請將已核實的發表管道要求與明確的專案/指導教授偏好作為已分類的疊加層套用。當數值能增進主要答案的清晰度且有證據支持時，請使用數值；即使省略了數值，仍應保留有意義的比較。

組合另一個摘要寫作技能時，請使用 [overlay-contract.md](overlay-contract.md) 對其規則進行分類。過往的六部分範本或禁用詞清單並非通用權威；切勿引入要求提出缺乏支持依據的主張或與使用中專案相衝突的指示。字數限制僅針對已確認的當前要求進行計算。可觀察到的陳腔濫調是一種可讀性診斷指標，絕不能作為 AI 撰寫的證明。

<a id="compression-and-standalone-checks"></a>
## 壓縮與獨立閱讀檢查

在縮短任一總結後，將其與當前的證據圖譜進行對照。檢查精簡過程中是否遺漏了分母、母體、基準線、時間範圍、僅適用於模型的限定條件或推論界線。確保描述性相似性未被寫成等價關係、模型規則未被寫成已證實的因果關係，且具條件限制的指標未被寫成整體的保護或脆弱性。

單獨閱讀精確的摘要。廣泛領域的讀者是否能說明其方法、研究任務、研究對象、相關處理範圍、主要答案與貢獻？單獨閱讀結論：它是否綜合歸納了實際研究，而非提出新的主張？在其他部分發生重大變更後，請重新檢查這兩部分。使用 [lifecycle-and-routing.md](lifecycle-and-routing.md) 進行章節結尾檢查，並使用 [prose-and-citation-editing.md](prose-and-citation-editing.md) 確保平實的學術句法。

針對說明研究主體定位的段落，首先僅從已完成的散文中改述作者試圖理解什麼、為達成該目標做了什麼，以及誰或何者在哪些維度與層級上被進行比較。接著將該解讀與權威規劃進行對照。一連串正確的 “we first / we then” 步驟、重複的 “comparison” 子句或模稜兩可的巢狀 “between” 片語，仍可能遺失研究目的或層次架構。請修復此種遺失，而非刪除能使比較保持清晰的技術性重複。移除 SQ 標籤絕不能同時移除其關聯性。若缺少權威依據，將限制評判結論；切勿為了填補開頭而憑空捏造目標。此項功能性檢查隸屬於既有的讀者演練流程，而非第二套檢核表，亦非未來助手將會遵循的證明。
