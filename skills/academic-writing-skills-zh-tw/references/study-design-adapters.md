<a id="shared-routing-questions"></a>
## 共用流程導引問題

針對每種研究設計，皆應詢問：觀察或產生了什麼實體、預期的比較或被估計量（estimand）為何、存在哪些相依性、呈現了何種不確定性，以及該設計允許何種推論。將缺漏的資訊回報為問題；切勿預設其採用了常規選擇。

<a id="quantitative-observational-and-survey"></a>
## 量化觀察型與調查研究

檢查抽樣底冊、納入與排除標準、遺漏值狀況、變項建構、測量品質、估計式假設、相依性、多重性（multiplicity）、效應大小、不確定性、子群體樣本數，以及組間差異是否經過直接檢定。

切勿直接推論樣本數不相等就必然需要獨立樣本檢定。請先判定觀察值是成對、巢套、重複測量、加權、叢集或獨立，並優先指明被估計量（estimand）。

對於潛在變項或結構模型，應區分測量適配度、結構適配度、標準化與非標準化係數、模型比較、群組不變性以及描述性路徑比較。測量品質不佳並非不可報告，但會收窄構念層級的主張。

在題項篩選後，應追溯施測量表 → 保留題項 → 得分意涵 → 使用該得分的主張。刪除題項可能會收窄構念，而無需變更原始問卷。題項用詞相同並不能證明測量等值；保留的題項組合不同，也不能證明施測了不同的問卷。應將這些問題與結構係數是否可報告或比較分開處理。

針對重複分析，在核對數值之前，應先確認觀察單位、執行選取／彙整方式、變異來源、檢定對比以及多重比較族群。當相同的原始檢定屬於不同的宣告比較族群時，不同的調整後 p 值皆可能有效。應區分模型內顯著性與直接的組間檢定，並區分不顯著與等值。對於計數，除數值外亦應比對事件定義：受影響的執行次數、警告事件與失敗紀錄不可混為一談。缺乏來源出處屬於核實問題，並非證明數值有誤。

<a id="experimental-and-quasi-experimental"></a>
## 實驗與準實驗

檢查分派、對照、處置忠實度、聲稱時的預先註冊、流失、干擾、統計檢定力、結果衡量時點、估計量、缺失值、多重結果、穩健性，以及因果表述是否與識別策略相符。

將處置效應與機制及探索性次群組發現區分開來。操弄檢核與中介變項必須有直接證據。

<a id="qualitative-and-mixed-methods"></a>
## 質性與混合研究方法

檢查抽樣邏輯、研究者角色、知情同意、資料產生、聲稱時的飽和度或資訊力、編碼過程、反思性、反例個案、引文佐證、稽核軌跡以及可轉移性。

若研究設計不允許，切勿將主題出現頻率轉化為母體盛行率。在混合方法中，應指出整合切入點，並說明結合不同研究主線相較於平行報告增加了哪些價值。

<a id="computational-and-simulation"></a>
## 計算與模擬

追溯來源資料 → 初始化 → 假設 → 演算法 → 耦合或狀態更新 → 校準 → 驗證（validation）或核驗（verification） → 情境 → 產出 → 主張。檢查基準線、隨機重複次數、敏感度、不確定性、參數出處、軟體版本以及可重現性產物。

區分程式碼核驗、實證驗證、預測表現、情境探索、機制表徵以及真實世界推論。

<a id="ai-and-llm-studies"></a>
## AI 與大型語言模型研究

檢查確切的模型識別碼與日期、系統與使用者提示詞、情境脈絡建構、對話狀態、抽樣設定、執行次數、可用時的隨機種子、剖析器與驗證邏輯、失敗情形、選定執行的規則、彙整方式、工作負載、有報告時的成本、資料保留、隱私以及可重現性產物的發布。

將每個以輸入為條件的屬性對應至產出主張。檢驗報告的模式是否可能直接源自提示詞條件設定、分組問題、共享設定檔、狀態洩漏或模型架構。僅在主張取決於區分這些解釋時，才要求進行消融實驗；否則應陳述其限制。

針對連結至相同來源設定檔的重複合成回應，在選取檢定之前，應先確認估計目標為邊際、成對、重複或階層式。在缺乏適當比較的情況下，切勿將個別的標準化係數視為相等或差異的正式證據。

當輸入設定檔改變而人類或其他參照基準維持固定時，
應將觀察到的對比歸因於該等輸入條件下的比較。
這並不能顯示參照母體會如何回應改變後的輸入，
且在缺乏專門檢驗該機制的證據前，也不能揭示模型內部機制。

<a id="evidence-synthesis"></a>
## 證據合成

檢查研究計畫書、檢索來源與日期、合格標準、篩選、萃取、偏差風險、合成方法、異質性、相關時的發表偏差、確定性，以及從納入研究到主張的可追溯性。

圍繞問題或合成邏輯組織研究發現，而非隨意的主題。區分證據量、一致性、效應大小、研究品質以及缺乏證據的情形。

<a id="theoretical-framework-methods-and-data-papers"></a>
## 理論、架構、方法與資料論文

梳理前提或需求 → 推導或設計 → 示範或評估 → 邊界條件 → 貢獻。當稿件已提供適當的證明、基準測試、個案示範、易用性評估或概念性論證時，切勿強求傳統的實證結果（Results）。

對於架構與資料論文，應區分整合的新穎性、實作品質、驗證證據、可重複使用性以及領域影響力。避免在未加限定的情況下，僅憑單一說明性個案就主張具有廣泛的實用性。
