# 修訂所要求的批註處理範圍

此程序適用於由 Word 批註、標註或選取文字所驅動的編輯。它適用於各類研究設計。選取範圍限制了預設的**編輯**處理範圍，而非必須**閱讀**的脈絡範圍。既有的最小變更原則依然適用；新增附註或完全無誤的掃描並無法證明已遵循這些原則。

<a id="establish-the-current-target-before-drafting"></a>
## 在起草前確立當前目標

1. 確認最新經作者/指導教授核准的檔案、其 SHA256、生效的修訂措辭以及實際的批註選取範圍。連同周圍的散文一併閱讀完整的批註與回覆討論串。切勿以包含該處的整段文字取代選取範圍、僅從批註文字推斷目標，或重複使用舊快照的 ID 或定位點。在任何來源變更後，請重讀定位錨點。
2. 記錄精簡的邊界：選取文字/定位點、所要求的動作、未變更的周圍文字，以及任何明確更廣泛的指示。帶有 “revise this section” 的標題錨點屬於章節層級的授權，而非僅限標題的工作。回覆隸屬於其既有討論串；它不會自動成為另一個獨立需求。請閱讀任何新的說明釐清，而非直接捨棄。
3. 區分提議措辭、編輯檔案、撰寫回覆與解決批註的權限。即使批註本身建議進行修訂，“Discuss first,” “do not edit,” 或 “no reply/resolution” 仍然具有約束力。當當前文字已滿足需求時，局部維持不變的答覆是有效的。

選填且唯讀的 `scripts/inspect_comment_targets.py DOCX` 回報快照雜湊值、批註文字/討論串連結、選取的 XML 文字、段落脈絡與定位錨點診斷。使用 `--expected-sha256 HASH` 來剔除過期的快照。請閱讀其具體產出；僅知道指令或語言掃描未發現相符項並不能算作定位錨點驗證。此輔助工具不是已註冊的配接器操作；使用者端需要明確的支援。它絕不會進行編輯、回覆、解決問題或授權。

其偏移量描述的是 XML 文字投影，而非 Word Range 位置、行號或呈現後的視圖。`range` 標識出可讀取的選取範圍，而非重寫它的核准。`point` 需要脈絡與該指示的處理範圍。僅含刪除或已刪除的定位錨點、缺失的端點/定義、多個定位錨點與未解決的討論串仍屬不確定狀態。切勿默認選取鄰近句子。協調重疊的選取範圍，並保留跨段落選取範圍的每個部分；兩者皆不意味著整份文件已解除鎖定。功能變數、繪圖、巢狀段落與不支援的結構可能需要專門的文件編輯器或檢查。

<a id="make-the-smallest-sufficient-revision"></a>
## 進行最小且充分的修訂

保留目標之外可用的作者/指導教授措辭以及既有已接受的編輯。即使在選取範圍內，亦應保留已發揮其功能的句子；其邊界並非改寫每個被選取單字的指示。切勿僅為了追求統一風格或通用範本而重寫引言、圖表說明、評分定義、方法／補充資料（SM）的指引或相鄰句子。無論在選取範圍之內或之外，皆應保留既有的讀者功能。必要的技術性重複並不代表獲准重新命名術語。

僅在有明確更廣泛的需求，或經證明的事實、交叉參照、文法或邏輯相依性時才擴大範圍。找出受影響的相鄰內容，說明若不處理該局部修改將會出現何種錯誤或難以閱讀，並僅變更該相依項目。切勿單獨將 “improving flow” 作為證據。尊重具體鎖定的相鄰內容：提出所需的變更並將該相依性標記為未解決，而非直接覆寫。重讀每個受影響的句子對與段落邊界。

指導教授過去的範例提供的是風格或論點結構，而非研究事實。請使用當前的數值、分組、測量指標與合適的措辭；切勿將舊數值、因果強度或未執行的分析複製到當前稿件中。當數值結果需要解讀時，將有支持依據的比較連結至其含義與相關問題，而不添加未要求的解釋。

<a id="verify-the-exact-candidate-and-report-the-actual-change"></a>
## 驗證精確的候選文字並回報實際變更

<a id="test-concern-closure-separately-from-edit-completion"></a>
### 將疑慮解決測試與編輯完成度分開檢驗

在現有的批註帳則或行內發現中，保留原始來源版本與選取範圍、完整的疑慮內容、精確的當前措辭及其定位點，以及該措辭為何能或不能解答該疑慮的理由。將原始選取範圍與包含該處的段落以及新的選取範圍分開處理：後續的改寫可能會移動範圍或改變其 ID 所選取的內容。該範圍標識了目標；周圍的散文則可能提供答案。

在確認批註已解決之前，先重述不熟悉背景的讀者必須能夠理解的內容，然後在當前的閱讀單元中定位該答案。針對邏輯批註，應詢問原本的誤解是否仍可能合理產生，而非僅看句子是否已被重寫。僅命名群組或分類規則，未必能解釋其比較為何重要；連接詞或更正的地名未必能補足缺失的研究依據。當研究發現看似衝突時，在推斷存在矛盾或已成功修復之前，應先區分產出結果、群組、分析層級與檢定。

在同一記錄內運用有根據的評估：

- **已解決：** 當前可用的措辭回答了該疑慮的每一個部分；有充分理由維持不變亦屬合格。請引用該答案，而不僅僅是回覆。
- **部分解決：** 同時指出已回答的部分以及仍留給讀者的疑問。切勿將整個討論串回報為已完成。
- **未解決：** 所需的關聯或更正仍缺失或不正確。
- **無法核實：** 指出缺失的來源/選取範圍/脈絡以及無法評判之處。即使未聲明其原始文件定位錨點已核實，仍可依據引用的批註來檢查顯見的文法更正。

這些是疑慮評估，而非新的稿件狀態或 Word 解決動作。針對部分解決、未解決或必要的無法核實疑慮，請將帳則狀態保持為 `OPEN`；僅在答案已核實時才使用 `RESOLVED`，且僅在既有的權威契約下才使用 `WAIVED`。分組回覆必須保留每個子疑慮的涵蓋面。應將此判斷與編輯/格式保留、字數檢查、語言掃描以及獨立讀者證據區分開來。保留已有成效的修改，而非為了展現工作量而重新改寫。請參閱
[evidence-context case 13](evidence-context-cases.md#13-a-rewrite-is-not-concern-closure)。

在選取範圍層級比較來源與候選版本。識別哪些句子發生變更，以及哪些周圍措辭保持完全一致。納入任何必要的擴展及其證據；若僅保留了主題，切勿聲稱段落未變更。即使候選版本文筆流暢，若帶有未經說明的超出處理範圍變更，亦應予以駁回。維持不變的候選版本仍必須回答實際的需求。

接著檢查修復後的單元是否保留其讀者導向、正確的數值與含義、內部/鄰近連結以及對該問題適用的答案。這些屬於內容檢查，而非要求添加 SQ 標籤或結尾範本。切勿僅為了在選取範圍之外獲得零差異而保留已損壞的相依性。

針對實際的 DOCX 編輯，亦請使用文件技能檢查已儲存的修訂視圖、既有的修訂者、批註/回覆關係以及可用的指導教授修改。絕不可為了圖方便而壓平段落、接受所有變更或解決討論串。單純文字相同並不能證明中繼資料或視覺效果已被保留。缺失的檢查仍屬未核實。若僅獲准提出提議，請回報提議內容及其精確差異；切勿暗示來源檔案、回覆或已解決狀態已發生變更。

### 假設性局部修復

Source: “Figure 4 compares the two groups. Scores use a 0–100 scale. **Group A
averaged 84.6 and group B 78.2. The difference is 6.4 points. This indicates higher
reported willingness in group A.** The instrument is described in Text S3.”

假設僅選取了粗體文字，作者要求連結結果與含義，且當前來源支持這些事實。一個充分的提議為：“Group A reported greater willingness than group B, with mean scores of 84.6
and 78.2, respectively, a difference of 6.4 points.” 開頭兩句與結尾的補充資料（SM）指引須完全保留。切勿增添實際購買行為、因果關係、顯著性或舊範例的數值。此範例並非規定的句子形式，亦非任何真實問卷的證據。
